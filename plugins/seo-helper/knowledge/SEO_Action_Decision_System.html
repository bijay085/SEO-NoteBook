1. Core Rule

Keep one main operating file. Add new rules into the correct section. Remove duplicate, weak, outdated, or conflicting points. Do not create a new system unless directly requested.

The goal is to answer with the exact action needed for the situation. Do not over-expand a simple task. Do not make assumptions when the business, entity, data, or page purpose is unclear.

Every SEO recommendation must have:

  • What: the exact action.
  • Why: the SEO, business, crawl, conversion, or trust reason.
  • How: how to check, audit, fix, publish, verify, or measure it.
  • Evidence: GSC, GA4, crawl data, SERP evidence, keyword tool data, site evidence, logs, or user-provided business information.
  • Priority: P0, P1, P2, or P3 with a reason.

Decision Tree Before Best Practice Rule

Use this when building or using the SEO Helper knowledgebase. The answer should follow an if/then diagnostic path before giving broad best practices. SEO advice changes by context, data pattern, page type, and recent site changes.

If This Happens Check This Before That Why
Impressions drop but average rankings do not move much. Check search demand, seasonality, SERP layout, country/device mix, and query mix before rewriting pages. The site may not have lost relevance; the market or SERP may have changed.
Rankings drop after a migration, redesign, CMS change, or URL change. Audit redirects, canonicals, indexability, robots, sitemaps, internal links, templates, and tracking before blaming content quality. Migration errors can hide as ranking losses.
Only a few pages lose traffic. Compare intent, current SERP winners, competitors, titles/snippets, internal links, and page freshness before changing the whole site. Small losses are often page/query specific, not site-wide strategy failures.
A core update overlaps the decline. Look for patterns by page type, intent, template, content quality, trust proof, and query class before changing everything. Core updates are broad reassessments; random fixes can make diagnosis harder.

Decision rule: answer as "If X, check Y before Z" whenever possible. A knowledgebase full of generic tips is weaker than one that routes symptoms to evidence and next actions.

Priority Formula

Use this formula when ranking tasks:

(Business impact + SEO impact + Confidence + Urgency) / Effort

Then adjust with page type. A money page usually outranks a blog page because it can directly produce revenue.

Google Ranking Update Monitoring Rule

Use this when someone asks whether a traffic or ranking change is caused by a Google update, or how to keep up with ranking-system changes. Google does not publish the full algorithm. Do not chase secrets. Monitor official sources, verify with site data, then decide whether action is needed.

Source or Signal What It Is For How to Use It
Google Search Status Dashboard Official confirmation of major Search incidents and ranking updates relevant to site owners. Check start date, end date, affected system, status, and linked guidance before blaming an update.
Google Search Central Blog Official Search announcements, core update posts, documentation changes, Search Console updates, and best-practice guidance. Subscribe by RSS or review when a major change is suspected. Use it as a primary source, not social-media summaries.
Google core update guidance and ranking systems guide Explains broad core updates, ranking systems, and why updates are usually broad reassessments rather than page-specific penalties. Use it to decide whether to improve content, authority, intent match, site quality, or technical access instead of making panic edits.
GSC and GA4 Shows whether the change is real for this site, page, query, country, device, and conversion path. Compare before, during, and after the update window. Segment by page type and query type. Do not rely only on total clicks.
Third-party volatility tools, publishers, and SEO professionals with large datasets Useful for early pattern detection, industry context, and hypotheses. Treat as supporting evidence only. They may see patterns before official guidance, but they are not final proof for your site.

Update Diagnosis Order

  1. Check whether Google has officially confirmed a ranking update, Search incident, crawl issue, indexing issue, or serving issue.
  2. Record the exact rollout start date, end date, affected system, and guidance link.
  3. In GSC, compare the affected period against a clean previous period. Avoid reading one noisy day as a conclusion.
  4. Split by page type: money pages, service pages, location pages, category pages, product pages, blog pages, tools, directories, and support content.
  5. Split by query type: brand, non-brand, commercial, informational, local, comparison, navigational, and AI/answer-heavy queries.
  6. Check whether the loss started before the confirmed update. If yes, the update may not be the main cause.
  7. Check technical basics before rewriting: robots, noindex, canonical, redirects, status codes, sitemap, rendering, internal links, server errors, manual actions, and crawl stats.
  8. Review the current SERP. Confirm whether intent, page type, AI Overviews, local pack, videos, forums, ads, or competitors changed.
  9. Only after evidence is clear, create actions: improve intent match, strengthen content, add proof, improve internal links, fix technical blockers, build authority, consolidate weak content, or wait and monitor.

Ranking Update Myth Busting

  • Myth: SEO professionals know exactly what changed in every update. Reality: outside Google, most update analysis is pattern-reading from limited data.
  • Myth: every drop during an update means Google penalized the site. Reality: broad updates can reassess relevance, helpfulness, authority, intent, duplication, links, or SERP needs.
  • Myth: the best response is immediate content rewriting. Reality: first rule out technical issues, tracking problems, SERP changes, cannibalization, and normal volatility.
  • Myth: fundamentals stop working after updates. Reality: clear intent, useful content, crawlable structure, good navigation, relevant internal links, real authority, clean UX, and trustworthy pages remain the base.
  • Myth: third-party metrics such as DR, DA, or volatility scores are Google metrics. Reality: they are estimates or tool-specific indicators, not Google ranking scores.

GEO Meaning Rule

The word Geo can mean different things. It can mean Generative Engine Optimization, a prefix meaning earth, or a coastal landform. In SEO work, if the context is AI search, treat GEO as Generative Engine Optimization.

Generative Engine Optimization focuses on getting content quoted, cited, summarized, or used directly inside AI-generated answers, such as ChatGPT-style answers, Google AI Overviews, Bing Copilot answers, and other answer engines. It is different from only ranking high in a traditional blue-link list.

For GEO, content needs high clarity, factual authority, easy-to-extract structure, consistent entity naming, visible proof, and strong external brand citations. Do not create hidden prompt-style content or manipulative AI instructions. Focus on clear facts, trusted sources, real expertise, and independently verifiable statements.

AEO, GEO, and AI SEO Reality Rule

Do not sell AEO or GEO as a separate magic discipline. Treat it as an AI-search layer of SEO, content quality, brand positioning, entity consistency, technical accessibility, and measurement.
Claim Reality Correct Action
"AEO/GEO replaces SEO." False. Strong SEO fundamentals are still the base: crawlability, helpful content, intent match, authority, internal links, speed, UX, and trust. Fix SEO foundations first. Do not create a separate AI package if the basics are weak.
"AEO/GEO is only a scam buzzword." Partly true, partly incomplete. The terms are often oversold, but AI answers, citations, referrals, and brand mentions are real surfaces to monitor. Use plain language: AI search visibility, AI citations, AI referrals, brand mentions, and answer inclusion.
"Good SEO automatically gets AI citations." Not guaranteed. AI systems may prefer pages with clear answer-first facts, consistent entity data, external mentions, listicle/review context, and accessible retrieval. Keep SEO strong, then improve extractable facts, brand consistency, source quality, and off-site mentions.
"AI visibility can be tracked perfectly." False. Prompt tracking is directional. GA4 referrals and server logs are more concrete, but still incomplete. Track AI referral traffic, conversions, branded search, fixed prompt checks, cited URLs, sentiment, and source consistency. Label uncertainty clearly.
"Technical SEO alone creates AI visibility." False. Technical fixes restore access and clarity, but do not create authority by themselves. Combine clean technical access with content quality, external validation, brand mentions, links, reviews, and useful data.
  • If a client asks for GEO or AEO, translate the request into plain actions: what AI systems say about the brand, which sources they use, whether pages are retrievable, and whether facts are clear enough to quote.
  • Do not invoice or plan duplicate work under a new acronym if the tasks are already normal SEO tasks.
  • Use "AI SEO" as a simple umbrella when explaining to non-technical stakeholders, but define the actual deliverables.
  • Best honest framing: AI search optimization is not a replacement for SEO. It is measurement plus a content, entity, brand, and access layer on top of SEO.

4. Simple SEO Working Model

Use this section when the task is basic SEO explanation, new-site planning, or deciding what to do first. Keep it simple enough to act on, but do not pretend SEO is one universal checklist.

Plain SEO Definition

SEO means improving the website, content, and trust signals so search systems can discover, understand, rank, and cite the right page for the right user intent.

Simple Loop

  1. Find a question, keyword, need, or problem that can lead to business value.
  2. Understand the search intent behind it.
  3. Create or improve the page that best answers that intent.
  4. Create supporting content around the same topic when the topic needs depth.
  5. Link the related pages together with clear internal links.
  6. Make sure Google can crawl, render, index, and understand the pages.
  7. Build authority through real proof, mentions, links, reviews, citations, and usefulness.
  8. Track results in GSC and GA4, then improve what is working and fix what is not.

Simple SEO With AI Beginner Loop

Use this when someone wants a simple practical SEO process with AI. Keep the workflow small enough for one person to execute. AI can speed research, outlines, grouping, and QA, but it must not replace checking real search results, business fit, or page usefulness.

Step What to Do Use AI For Human Check
1. Pick one narrow niche or topic. Choose one clear audience, problem, service, product, or topic cluster instead of going broad. Brainstorm audience problems, subtopics, pain points, and related questions. Confirm the topic has business value and you can actually create useful content for it.
2. Find real queries. Collect 10 to 30 real searches from Google autocomplete, People Also Ask, Reddit/forums, GSC if available, sales questions, support questions, and competitor pages. Group rough ideas and turn messy questions into clean query lists. Validate against live SERPs. Do not trust AI keyword ideas without search-result confirmation.
3. Group by same intent. Put queries with the same user need together. Separate queries that need different page types. Cluster queries, identify parent topics, and suggest one main page plus support pages. Read the top results yourself. If the SERP changes page type, split the group.
4. Build one main page and support pages. Create a main page for the primary intent and a few support pages for related sub-intents. Draft outlines, headings, FAQs only when needed, schema drafts, and internal-link ideas. Add real examples, screenshots, data, experience, product/service details, and source checks.
5. Optimize basics. Use clear title, URL, H1, headings, intro answer, scannable sections, internal links, image alt text, meta description, and schema where accurate. Find missing basics and QA the page against the brief. Check that the page reads naturally and answers the query without stuffing keywords.
6. Publish and connect. Publish the page, submit sitemap/indexing where appropriate, and add contextual internal links from relevant existing pages. Suggest source pages, anchors, related pages, and post-publish checks. Confirm the live page renders correctly and links make sense for users.
7. Share and build trust. Share in relevant communities, create useful supporting assets, earn mentions/links, collect reviews if local, and repurpose where appropriate. Prepare outreach ideas, repurposing angles, and community-friendly summaries. Avoid spam. Only share where the content genuinely helps.
8. Update from data. Check GSC weekly. Improve pages with impressions, weak CTR, page 2 rankings, query drift, or conversion gaps. Summarize GSC changes, suggest refreshes, identify missing answers, and draft updates. Prioritize pages by business value and do not change everything at once.
  • Simple starting setup: one topic, 10 related same-intent queries, one main page, a few support pages, internal links, weekly GSC review.
  • Use AI for skeleton, organization, speed, and QA. Use human input for experience, judgment, examples, screenshots, original data, and final approval.
  • Do not chase low-competition keywords blindly. A weak keyword with wrong intent can waste more time than a harder query with real business value.
  • Myth: AI makes SEO complicated. Reality: AI should make the basic loop faster while the fundamentals stay the same.

SEO Myth Filter Rule

Use this when a client, team, agency, or tool claims a simple SEO shortcut will solve the whole problem. Convert every claim into evidence, risk, business impact, and acceptance criteria before acting.

Myth Reality Better Action
More content means more traffic or customers. More pages only help when they match real intent, belong in the topic structure, and support the sales or user journey. Publish fewer stronger pages first. Expand only when the new page has distinct intent and business value.
Longer content always wins. Length is not the goal. The page must answer the exact intent with enough depth, clarity, proof, and usefulness. Match the content depth to the SERP, page type, user need, and conversion path.
Just add more keywords. Keyword stuffing can make content robotic, unclear, and lower quality. Use natural language, entities, headings, examples, and sections that answer the query.
More backlinks automatically mean better rankings. Relevance, trust, placement, page quality, and risk matter more than raw link count. Prioritize relevant mentions, real partnerships, digital PR, citations, and links that make sense.
SEO plugin score or tool score equals SEO success. Scores can catch basics, but green lights do not prove intent match, authority, conversion value, or ranking ability. Use scores as QA checks, then validate with crawl, SERP, GSC, GA4, and business data.
Ranking number 1 solves everything. Ranking without the right intent, offer, trust, CTA, and conversion path may produce little revenue. Measure qualified traffic, calls, leads, signups, sales, assisted conversions, and lead quality.
Titles and meta descriptions do not matter because Google can rewrite them. Google may rewrite snippets, but strong titles and descriptions still help define relevance and improve CTR. Write clear metadata based on page intent, query language, offer, and differentiation.
SEO is instant or one-time. SEO compounds through repeated technical maintenance, content improvement, authority building, and measurement. Work in milestones: baseline, fixes, publishing, indexing, ranking movement, conversion improvement, and refresh cycle.
Only Google matters. Google is usually primary, but discovery can also happen through Bing, YouTube, marketplaces, maps, social platforms, forums, and AI answers. Prioritize by audience and business model. Do not ignore channels that influence buyer discovery.
AI content is automatically penalized, or AI content automatically wins. Low-value content is the risk. AI can help draft, analyze, or structure, but origin alone does not prove quality. Require intent fit, original value, expert review, proof, source accuracy, and useful structure.
DA, DR, or third-party authority scores are Google KPIs. They are third-party metrics, useful for comparison but not Google ranking data. Use them as directional context only. Prioritize qualified traffic, conversions, rankings, indexed pages, and relevant links.
GEO, AEO, or AI visibility is a magic replacement for SEO. AI visibility mostly depends on strong SEO foundations, clear entities, trustworthy sources, extractable facts, and brand mentions. Improve crawlable content, structured facts, external citations, reputation, and answer clarity.
Schema alone will rank the page. Schema helps search systems understand eligible facts. It does not replace content quality, authority, or intent match. Add accurate structured data only when it matches visible page content and page type.
Disavow is the default fix for bad backlinks. Most sites should not panic over random spam links. Disavow is for specific serious link-risk situations. Investigate manual actions, link schemes, unnatural patterns, and actual risk before using disavow.
  • If a claim sounds like a guaranteed shortcut, ask for evidence, affected URLs, expected KPI, timeframe, risk, and what will be done if it fails.
  • Do not let myth-busting become anti-action. The correct response to a bad shortcut is a better decision rule, not doing nothing.
  • Myth: SEO has secret sauce. Reality: durable SEO is mostly correct prioritization, useful pages, technical access, trust, links/mentions, UX, and iteration.

Page Title Length and Rewrite Rule

Use this when someone asks whether a title must stay near 60 characters. Treat 60 characters as a display guideline, not a ranking law. The title should serve page targeting, intent, query language, and click clarity.

Question Decision How to Apply
Should every title be under 60 characters? No fixed rule. Put the most important query, intent, and differentiator early. Let the title run longer if the extra terms are relevant and not stuffed.
Does Google read beyond the visible snippet? Often yes, but display is not guaranteed. Do not remove important relevance just to satisfy a character counter. Remember display truncation depends on pixel width and Google may rewrite titles.
Should titles optimize for CTR or ranking? Both, but ranking relevance usually comes first when the page is not already winning. For low-authority or underperforming pages, include the strongest real queries from GSC and the main intent before adding brand or marketing language.
Where should brand go? Usually at the end unless brand is the reason to click. Use brand at the end for normal non-brand pages. Put brand first only for brand-led, trust-led, or navigational pages.
What about meta descriptions? Write natural page summaries, not character-counter text. Include the target query or supporting terms naturally, explain the page value, and give users a reason to click where appropriate.
  • Compare competitor titles, but do not copy their length blindly.
  • If CTR is weak while position is stable, test title/meta changes and annotate the date.
  • If rankings are weak, first check intent, page quality, internal links, topical authority, and whether the title targets the right query set.
  • Myth: title tags stop mattering because Google rewrites them. Reality: rewrites happen, but the title tag is still a strong relevance and QA signal.

Underrated SEO Action Rule

Use this when looking for practical actions that can produce results without inventing a new strategy. These are not universal hacks. Apply them only when they match the page type, business model, and evidence.

Action Use When How to Do It Risk or Limit
Refresh old pages. The page has impressions, old facts, stale year/date, weaker CTR, page 2 rankings, or query drift. Update facts, examples, screenshots, sections, title, meta description, internal links, and answer completeness. Annotate the change. Do not fake freshness by only changing the date. Refresh must improve the page.
Add real customer questions. Product, service, support, and local pages miss questions users actually ask before buying or contacting. Add only questions that support intent or conversion.
Use GSC queries on relevant pages. A page already gets impressions for useful queries it does not answer clearly. Add one or two high-value queries and direct answers naturally into the page, not as a dumped keyword list. Prioritize revenue or qualified-intent queries, not every accidental query.
Improve contextual internal links. Important pages are orphaned, too deep, weakly linked, or need support from related content. Add paragraph-level links from relevant pages with natural anchors and clear reason. Do not link every sibling page or repeat exact-match anchors everywhere.
Test better titles and meta descriptions. A page has impressions but low CTR, unclear positioning, or weak snippet language. Write for human click intent first, then include the core query and differentiator. Let the title be as long as needed if it remains clear. Do not obey a fixed 60-character title myth if it weakens clarity. Also do not stuff multiple unrelated intents.
Create comparison or alternative pages. Users compare options, competitors, products, services, tools, or approaches before converting. Build honest comparison pages with use cases, tradeoffs, pricing context, feature differences, proof, and CTAs. Do not create fake or biased comparison pages with no real analysis.
Create useful media assets. The niche can benefit from original photos, charts, screenshots, templates, tools, diagrams, or videos. Publish assets on the site and distribute where relevant. If others use original images/assets, ask for proper attribution or links politely. Check licensing, brand safety, and relevance. Do not use assets mainly for manipulative link schemes.
Use image SEO properly. Products, local work, recipes, travel, design, ecommerce, and visual niches can gain image visibility. Use descriptive file names, alt text, captions where helpful, compressed images, original media, and image sitemap support when needed. Do not keyword-stuff image names or alt text.
Build a natural review rhythm. Local businesses rely on GBP, maps, trust, calls, or bookings. Ask real customers steadily after service, encourage specific honest reviews, reply to reviews, and avoid batches or scripts. Do not incentivize, gate, fake, or bulk-create reviews.
Cross-link YouTube and page content. A topic benefits from demonstration, walkthrough, tutorial, product explanation, or trust-building video. Embed the useful video on the page and link from the video description back to the relevant page. Video must add clarity. Do not embed unrelated videos just to fill the page.
Fix pagination and crawl paths. Large categories, product lists, directories, or archives hide important items behind weak JavaScript loading or broken pagination. Use crawlable pagination or stable URLs for important deeper pages and ensure internal links expose valuable content. Infinite scroll or load-more can hide content if not implemented with crawlable URLs.
Check CDN and firewall settings. GSC shows robots, sitemap, crawl, or fetch errors while pages appear fine in a browser. Check Cloudflare/WAF/bot protection, TLS behavior, Googlebot access, caching, redirects, and server responses. Browser 200 status is not enough. Test as crawler where possible.
  • Most underrated SEO actions work because they improve relevance, crawl paths, trust, snippets, or conversion friction, not because they are secret tricks.
  • Prefer actions on pages with existing evidence: impressions, rankings, conversions, backlinks, internal authority, or business value.
  • Myth: underrated tips are universal hacks. Reality: they only work when the condition matches the site and the execution is clean.

Ranking Factor, Signal, and Context Rule

Use this when someone treats every SEO item as equal. Separate the things a page sends as signals from the larger factors and context that decide whether those signals matter.

Layer Examples How to Use
Signals. Title, headings, body text, language, schema, internal anchor text, image alt text, buttons, page speed, hosting, canonicals, and structured facts. Make each signal clean, accurate, crawlable, and aligned with the intended page purpose.
Factors or multipliers. Topical authority, external authority, user satisfaction, brand trust, internal architecture, historical performance, and SERP fit. Use these to decide why two pages with similar signals perform differently.
Context. Search intent, entity behind the site, business model, page type, country, device, seasonality, competition, and query specificity. Interpret every signal and factor through context before prioritizing work.
  • Do not over-optimize a signal if the factor or context is wrong. A better title cannot fix a page that answers the wrong intent.
  • Do not ignore small signals either. Clean signals help search systems understand the page, especially when stronger factors already exist.
  • Myth: one ranking factor explains performance. Reality: ranking is the result of signals, larger factors, and context interacting.

5. SEO KPI Forecasting Rules

Use this section when a client asks for projections, targets, expected clicks, impressions, CTR, rankings, conversions, or growth timelines.

New Site Forecasting Rule

For a brand-new website, do not promise exact clicks, impressions, CTR, leads, or revenue after only 3 months. There are too many uncontrolled variables: indexing speed, competition, domain authority, content quality, SERP changes, backlinks, internal linking, and Google updates.

What to Forecast First

Forecast Type Good Early KPI Why
Execution Pages published, service pages added, content briefs completed, technical fixes shipped, outreach emails sent. These are controllable deliverables.
Discovery Pages crawled, pages indexed, sitemap URLs discovered, GSC impressions starting. New sites need discovery before reliable traffic forecasting.
Keyword movement Keywords entering Top 100, Top 50, Top 30, Top 20, Top 10. Ranking milestones are better early signals than clicks alone.
Authority Referring domains, quality backlinks, mentions, citations, review growth, branded search. Authority compounds slowly and affects later ranking potential.
Traffic Organic impressions, clicks, CTR, non-branded clicks, landing page sessions. Use these after baseline data exists. Treat early numbers as directional.

Scenario Forecast Method

  1. Build Conservative, Expected, and Optimistic scenarios.
  2. State assumptions clearly: number of pages published, indexing rate, backlink rate, keyword difficulty, search volume, internal linking, content quality, and competitor strength.
  3. Estimate page indexing first, then ranking milestone movement, then possible impressions, then possible clicks using realistic CTR ranges by expected ranking position.
  4. Use competitor benchmarks only from sites with similar authority, content type, market, and publishing model.
  5. Update the forecast monthly with real GSC data.
  6. After 3 months, replace assumption-heavy forecasts with observed data trends where possible.

Forecast Timeline

Timeframe Best Measurement Warning
0 to 3 months Execution, indexing, early impressions, early Top 100 and Top 50 keywords. Clicks and CTR may be too unstable to promise.
3 to 6 months Ranking movement, content clusters gaining impressions, first meaningful clicks, internal link impact. Still use ranges, not fixed promises.
6 to 12 months Non-branded traffic growth, Top 10 growth, conversions, assisted conversions, backlink and authority impact. Compare against actual baseline and seasonality.

Client Communication Rule

If the client demands numbers, give ranges with assumptions. Say clearly that early traffic and CTR are outcomes, not guaranteed deliverables. This is cleaner than making confident numbers that the data cannot support.

8. New Website, Business, or Topic Understanding

Before any large work, understand the business or topic without being over-smart. Do not force a template from another niche. Do not copy an existing sheet. Use templates only as references for thinking.

Required First Questions

Question Reason How to Check
What is the domain about? Prevents irrelevant keyword and page plans. Read homepage, about page, navigation, service/product pages, schema, footer, GBP, and social profiles.
What is the central entity? Topical maps must grow from the real business entity, not random keywords. Extract the main entity, sub-entities, attributes, values, use cases, audience, and monetization method.
What does the business actually do? Prevents publishing pages for services or products the business does not provide. Use business pages, FAQs, intake answers, contact page, pricing, case studies, and client confirmation.

Entity, Attribute, Value Method

Use EAV for domain understanding and topical map creation:

  • Entity: the core business or topic, such as food photography, garage door repair, retirement planning, or accounting software.
  • Attributes: the dimensions people use to search, compare, buy, learn, or solve problems.
  • Values: the child terms under each attribute.
  • Intent: get, buy, hire, compare, learn, fix, calculate, choose, or verify.
  • ICP: the audience that buys or benefits.
  • Bridge: the business model, method, technology, or positioning that connects broad demand to the actual offer.
  • Convincing dimensions: reasons to choose the business, such as cost, speed, authority, lower effort, risk reduction, proof, availability, location, or quality.
  • Conclusion: the page, offer, or action the user should reach.

Direct Targeting vs Funnel Targeting

Demand Condition Decision Reason
The exact entity or working method has search volume and SERP support. Target it directly with a money page or strong landing page. People already know the concept and are searching for it.
The exact entity has low volume but appears in SERPs or related SERP features. Start direct targeting slowly and support it with broader pages. The market may understand the concept, but demand is still small.
The exact entity has no volume and no meaningful SERP trigger. Do not rely on direct entity targeting. Enter through broader known topics, then bridge to the offer. People do not yet search that working method. Ranking pages must begin from known demand.

Australian and international content are genuinely different. Keep separate country URLs, such as example.com.au/page and example.com/page, with self-referencing canonicals and matching hreflang. Content is mostly identical and only changes by IP or visitor location. Choose one canonical domain or create proper localized URLs with real differences. Two indexable domains with the same content create duplication and Google may choose one version. Do not promise that both domains retain SEO independently.
Users should stay on the chosen country domain. Use a country selector, remember user choice, and avoid forced redirects when possible. IP detection can be wrong because of VPNs, travel, corporate networks, and crawler location. Suggest, do not force, unless there is a legal or operational requirement.
Same WordPress installation serves multiple domains. Use WordPress multisite, WPML domain-per-language/region setup, or carefully engineered host-based routing. Plugins, home_url(), canonical tags, sitemaps, media URLs, redirects, and SEO plugins may assume one primary domain. Prefer multisite or a mature multilingual/regional setup over hardcoded domain tricks.
Google needs to understand regional alternatives. Use reciprocal hreflang across domains, correct language-region codes such as en-AU, and x-default where appropriate. Hreflang is not a duplicate-content shield and does not replace canonical or content differentiation. Use hreflang only between equivalent regional pages that are both crawlable and indexable.
  • Do not show different indexable content only through IP-based conditional display on the same URL. Search engines may only see one version.
  • Do not geo-redirect Googlebot differently from users. If redirects are used, they must be consistent, crawlable, and not hide important regional URLs.
  • Each regional version needs its own title, H1, content, pricing, shipping/service terms, currency, phone, address or service area, reviews, legal details, sitemap, and internal links where relevant.
  • If the client wants to "retain SEO" from both domains, explain that signals do not simply stack because two domains point to one backend. The URL, canonical, redirect, hreflang, and content strategy decide what can rank.
  • Myth: hreflang makes duplicate pages distinct. Reality: hreflang tells Google about regional alternatives; it works best when each URL is crawlable, self-canonical, and meaningfully appropriate for its market.

New Domain Content Volume Rule

Use this when deciding whether a new website should launch or scale with 10, 50, 100, 500, or more pages. There is no universal safe page count. Too much content means more pages than the site can make useful, differentiated, index-worthy, internally linked, and maintained.

Question Good Answer Bad Answer Decision
Does each page have a clear purpose? Yes, it answers a real user need, business need, or search intent. No, it exists because a keyword list had more rows. Publish only the purposeful pages.
Does each page add unique value? Yes, with original details, examples, data, proof, local facts, comparisons, or first-hand experience. No, it repeats the same generic article with different wording. Merge, hold, or improve before publishing.
Can the site support the pages? Pages have internal links, templates, metadata, crawl paths, author/reviewer rules, and update ownership. Pages are dumped into the site without structure or maintenance. Build structure before scaling.

Is publishing pace protecting quality? The team can research, write, QA, interlink, publish, and refresh at that pace. The pace forces slop, duplication, weak editing, or no feedback loop. Slow down and improve the process.

  • Publishing 10 strong pages can be better than publishing 500 weak pages. Publishing 500 can be fine only if the pages are genuinely useful, distinct, structured, and maintained.
  • If page creation starts feeling like keyword shoehorning, stop and re-evaluate the topical map.
  • If many pages are not indexed or have no impressions after reasonable crawl time, do not keep adding more of the same. Fix page quality, intent overlap, internal links, crawl paths, and authority first.
  • Myth: Google punishes a new site just for publishing many pages. Reality: the risk is scaled low-value content, duplication, weak purpose, poor structure, and no maintenance.

Local Website Conversion Rule

Use this when the goal is more calls, bookings, quote requests, form fills, purchases, or local leads from existing traffic. Conversion work starts by reducing buyer friction, not by adding more words or more visual noise.

Conversion Problem Why It Hurts Required Fix
Page is hard to scan. Busy users do not read large blocks before deciding whether to trust or contact the business. Use clear headings, short sections, bullets, tables, direct answers, visible proof, and obvious next steps.

Distracting monetization reduces trust, especially for local service, professional, health, legal, and home-service pages. Remove or reduce ads on money pages. Call to Action SEO and Conversion Rule

A call to action is a prompt that tells the user the next useful action to take. In SEO work, the CTA must match the page intent, buyer stage, traffic source, and trust level. A CTA should not fight the content or turn a helpful page into a hard sell.

Page or Channel Best CTA Type Examples Rule
Lead generation page. Direct lead CTA. Get Quote, Contact Us, Book Consultation, Apply Now, Request Estimate. Make the action visible above the fold and after proof sections. Keep forms short enough for the offer.
Product or ecommerce page. Purchase CTA. Shop Now, Order Now, Pre-Order, Add to Cart, Start Checkout. Place near price, availability, reviews, delivery, and return information.
Content or blog page. Contextual next-step CTA. Download Guide, View Product, See Menu, Try Tool, Compare Options, Learn More. Add the CTA after value is delivered, and optionally between early paragraphs if it naturally matches the problem.
Local service page. Contact or booking CTA. Call Now, Book Service, Request Same-Day Help, Get Local Quote. Use mobile click-to-call, sticky contact where appropriate, service-area proof, and visible trust near the CTA.
Reddit or community post. Soft conversational CTA. Has anyone tested this in another niche? What would you check next? I can share the checklist if useful. Avoid hard selling, link dropping, and aggressive "buy/sign up now" language unless the subreddit and context allow it.
Reddit Ads or paid ads. Clear ad CTA backed by landing page. Sign Up, Get Quote, Shop Now, Download, Install, See Menu, Order Now. Ad CTA can be direct, but the landing page must deliver the same promise without extra friction.

CTA Design and Copy Checklist

  1. Finish the sentence from the user's point of view: "I want to..."
  2. Use action verbs: get, book, call, compare, download, start, try, shop, order, apply, view, or contact.
  3. State the user benefit, not only the business goal.
  4. Keep the CTA short, clear, and honest. Do not use vague labels such as "Submit" when a specific action is possible.
  5. Use one primary CTA per page or screen area. A secondary CTA is allowed when it serves a different stage, such as "Learn More".
  6. Place CTAs above the fold, beside relevant proof or offer details, after useful content, and at the end of the page.
  7. Make the CTA visually obvious, mobile-friendly, and easy to tap without layout shift.
  8. Use urgency or scarcity only when real. Fake countdowns and permanent "limited time" offers reduce trust.
  9. Add social proof near important CTAs when real: reviews, testimonials, ratings, case results, customers served, certifications, or guarantees.
  10. Track CTA clicks, form starts, form completions, calls, booking clicks, checkout starts, purchases, and lead quality.

Updating a Ranking Blog Post With a CTA

Use this when a blog post already gets traffic but sends little traffic or revenue to the product, service, or money page.

Condition Decision Reason
Only adding a relevant button, internal link, product block, or short CTA. Usually safe. A contextual internal link to a relevant money page should not hurt rankings by itself.
Changing the core topic, title, intent, or main content of a winning post. Be careful and document changes. Large intent changes can affect the page's ranking fit.
Post is still climbing in rankings and traffic. Prefer light CTA changes or wait until the trend stabilizes if risk is high. It is easier to measure conversion impact after traffic reaches a steadier baseline.
Post has low traffic. Do not call it a statistically valid A/B test. Use before/after monitoring, annotations, and practical judgment instead of pretending the sample is strong.
CTA improves conversion but lowers pageviews or rankings. Judge by total business outcome. Use the simple equation: traffic times conversion rate equals business outcome. Higher conversion is not useful if traffic loss creates less revenue.
  • Best first test: add one contextual CTA where the user has just learned enough to want the next step.
  • Keep the CTA related to the surrounding paragraph. Do not interrupt informational intent with a random hard sell.
  • Monitor for at least a reasonable period, often around 30 days when traffic volume is small and seasonality is low.
  • If performance drops after a CTA-only change, revert or test a softer placement. Do not panic-rewrite the full post first.

CTA Mistake Rule

  • Too many CTAs create decision friction. Prioritize the one action that matters most for the page.
  • A misleading CTA breaks trust and can hurt conversion even if clicks rise.
  • A CTA without supporting proof is weak. Add reviews, benefits, pricing context, examples, guarantees, screenshots, or process details nearby.
  • A hard-sell CTA on Reddit or community platforms can create downvotes, removals, negative brand mentions, or bans. Use value-first participation and soft discussion prompts.
  • A CTA click is not the final win. The landing page, form, phone handling, checkout, booking, or follow-up must complete the promise.

GBP Posts Rule

GBP posts can share updates, offers, events, photos, videos, and timely business information. They are useful for customer experience and profile freshness, but do not treat posting alone as a guaranteed ranking lever.

Best framing: GBP posts are engagement and profile-trust assets. They can support clicks, calls, bookings, and freshness, but they are not a reliable direct map-pack ranking lever by themselves.
Business Situation Post Frequency What to Post
Active local service business. 1 post per week is a practical target if there is useful content. At minimum, post monthly. Recent job, service reminder, seasonal issue, new location proof, FAQ, offer, booking reminder, team update, case result.
Restaurant, retail, event, appointment, or inventory-driven business. 1 to 3 posts per week when there are real updates. Menu, offer, event, new product, in-stock item, booking, seasonal promotion, customer-facing update.
Low-change professional service. Monthly or when there is real news. Service explanation, trust update, team update, office hours, case study, appointment availability, educational snippet.
Regulated or restricted category. Only post if allowed by Google policy. Non-restricted business updates. Avoid prohibited product claims, phone stuffing, policy-risk content, and restricted offers.

  • Use posts when there is a real update, job, case study, offer, menu item, availability, event, seasonal reminder, or useful local content.

Worked on Everything but No Recovery Rule

When someone says they improved on-page SEO, content, E-E-A-T, and backlinks but rankings did not return, reject the broad answer "Google update" until the loss is decomposed.

  1. Find the exact decline window in GSC by page, query, impressions, clicks, CTR, and average position.
  2. Separate ranking loss from CTR loss, demand loss, cannibalization, and SERP feature displacement.
  3. Compare old winners and current winners for intent, page type, format, content length, freshness, and trust signals.
  4. Check whether visible E-E-A-T changes are only cosmetic or actually improve proof, author credibility, reviews, citations, and user confidence.
  5. Use behavior tools such as GA4 or Clarity to look for mismatch signals: short engagement, rage clicks, weak scroll, or poor CTA interaction.
  6. If the SERP did not change, inspect indexability, canonicals, crawl access, internal links, template changes, lost links, and stronger competitor movement.

Decision rule: if broad SEO work creates no movement, the real issue is usually narrower than the work list. Diagnose the changed query/page/SERP relationship before adding more fixes.

Organic Uncertainty and Paid Fallback Rule

SEO is controllable in inputs, not guaranteed in outcomes. Similar domains are rarely truly identical, but some markets have more qualified pages than valuable organic positions.

  • Do not assume every non-ranking site has one obvious mistake.
  • Still check hidden differences: topical authority, crawl priority, internal link depth, brand demand, backlink quality, and intent fit.
  • Do not let a business model depend only on organic traffic appearing on schedule.
  • Use Google Ads, partnerships, email, social, referral traffic, or direct sales as risk controls while SEO compounds.

Page Two Intent Correction Rule

If a page is indexed, linked, and keyword-targeted but stuck on page two, inspect the SERP before prescribing more backlinks.

  • The SERP is the brief: compare top-ranking page type, content length, answer directness, title promise, freshness, and conversion path.
  • If winners are short and direct, a longer page may be over-answering the query.
  • If titles are keyword-stuffed, rewrite them around searcher reason-to-click, not only keyword coverage.
  • After structural and title changes, wait long enough to measure movement before changing another major variable.

Myth Reality Rule
LLMs.txt will solve AI visibility. It is not a universal ranking or citation lever. Do not prioritize it above crawlability, content quality, brand consistency, and real citations.

Agentic SEO Reality Check Rule

Use this when someone asks whether agentic SEO really works or whether it is only AI-generated noise. The answer depends on what is automated. Automating research, QA, monitoring, and workflow can help. Automating authority, strategy, originality, and publishing judgment is the danger zone.

Data plumbing. Pulling GSC, GA4, crawl data, PageSpeed, rank data, broken links, page inventory, and change logs into one workflow. Making decisions from one metric, stale exports, or unverified AI summaries. Every agent summary must link back to the source metric, page, or crawl evidence.
Topic maps and clustering. Grouping keywords, finding gaps, detecting cannibalization, and proposing hubs/sub-hubs. Creating pages because keywords exist, without checking page purpose or business fit. Approve the information structure before generating copy.
Content refresh. Finding stale pages, query drift, missing sections, weak snippets, and pages stuck near page one or page two. Rewriting every underperforming page automatically and killing pages that needed time or internal links. Diagnose page stage first: indexation, impressions, CTR, position, qualified visits, CTA action, revenue.
Internal links. Suggesting contextual links based on topical relationship, crawl depth, orphan status, and receiving-page value. Linking every sibling page or forcing exact-match anchors everywhere. Require source URL, target URL, anchor, placement, and reason for every proposed link.
Content briefs and first drafts. Turning SERP analysis, notes, keyword groups, and source facts into a structured brief or rough draft. Publishing fluent content that adds no information gain, examples, experience, proof, or original angle. Human or SME must add proof, examples, experience, opinions, data, or business-specific detail.
Publishing. Publishing approved pages only after strict metadata, taxonomy, canonical, schema, link, CTA, and render checks pass. Auto-publishing large batches of generic content from weak prompts. Use post-publish contracts and fail closed on ranking, trust, or conversion-critical errors.
Authority. Finding legitimate mentions, partner opportunities, citation gaps, PR angles, and outreach research. Trying to automate trust with paid link schemes, bulk outreach, fake reviews, or shallow citations. Automate prospect research, not authority itself. Human approves link and reputation work.
AI visibility. Checking brand mentions, citation share, answer inclusion, extractable facts, and whether AI systems describe the brand correctly. Measuring only traffic while ignoring sourced answers, no-click visibility, and brand context. Track what AI systems say, which sources they cite, and whether the brand is recommended for the right queries.
  • Agentic SEO is strongest when it makes SEO operations faster, more consistent, and easier to audit.
  • The common failure mode is scaling average content, weak strategy, and weak authority faster than a human team could.
  • If an AI agent can create the whole page only by scraping existing public pages, the page may lack information gain. Add real experience, data, examples, proof, product knowledge, or expert judgment.
  • Do not treat traffic spikes as proof. Check whether performance holds after updates, whether traffic is qualified, and whether it creates business outcomes.
  • Myth: the choice is full human SEO or full agent SEO. Reality: the useful middle is agent-assisted systems with human strategy, source truth, and review gates.

Weekly Agentic SEO Operating Loop Rule

Use this when an SEO agent, Claude Code skill, Codex workflow, script, or automation reviews content, GSC metrics, and PageSpeed every week. This is a good first step, but it should become a monitored operating loop, not a blind automation system.

Weekly Input What the Agent Should Do Human Review or Guardrail Priority
GSC metrics. Compare clicks, impressions, CTR, average position, query changes, page changes, growing queries, and declining pages. Group by page type, intent, and business value. Approve actions by money value, intent match, and risk. Do not chase every small weekly movement. P1.
Content analysis. Find intent mismatch, missing sections, stale facts, weak proof, unclear entity coverage, irrelevant query coverage, and pages that need consolidation or expansion. Verify facts, sources, author authority, SME input, and whether the page still answers the exact query. P1 or P2.
PageSpeed and Core Web Vitals. Check LCP, INP, CLS, heavy images, heavy scripts, template-level bloat, render-blocking resources, and affected page templates. Developer review is required before technical edits. Prioritize money pages and templates affecting many URLs. P1 for money pages, otherwise P2.
Internal linking. Find orphan pages, pages with impressions but weak internal links, missing hub links, missing support links, weak anchor text, and pages that should pass authority to service or location pages. Check semantic fit. Do not create forced, spammy, or repeated exact-match internal links. P1 or P2.
Competitor monitoring. Track changes in titles, headings, SERP features, new pages, updated pages, comparison pages, content depth, schema, links, and brand mentions. Decide whether the competitor change actually affects the target intent before copying any idea. P2.
New content opportunities. Use GSC queries, SERP gaps, internal search, support questions, sales questions, competitor gaps, and entity gaps to propose briefs. Human approves the brief and page purpose before writing. Do not publish new content from a hunch only. P2.
Backlink and outreach opportunities. Research relevant blogs, partner pages, citations, directories, unlinked mentions, resource pages, and legitimate outreach targets. Human approves prospects and messages. No autopilot spam, paid link schemes, or irrelevant bulk outreach. P2.
Change log and performance log. Record what changed, when it changed, why it changed, affected URLs, owner, expected KPI, and 7, 28, and 90 day comparison windows. Check causality carefully. Improvement after an action is a signal, not proof by itself. P1.
  • Weekly agentic SEO is best as a monitoring, evidence gathering, recommendation, and QA loop.
  • Add competitor tracking, internal link checks, content opportunity scoring, and change logs to any setup that only checks GSC, content, and PageSpeed.
  • Do not change everything every week. Batch similar fixes, annotate changes, and wait long enough to compare results.
  • Early improvement such as moving from 0 or 1 click per day to around 10 clicks per day is useful evidence that the loop may be helping, but it does not prove every recommendation is correct.
  • No automatic publishing, no automatic redirects, no automatic noindex, no automatic schema changes, and no automatic outreach without review.
  • Myth: agentic SEO means run a skill and let it decide. Reality: the agent gathers evidence and drafts actions, while a human prioritizes by intent, risk, and business value.

Production Agentic SEO Pipeline Rule

Use this when an agentic SEO system moves beyond weekly checks and starts producing briefs, content, CMS updates, or publishing actions. A production pipeline needs clear ownership boundaries: the agent can execute repeatable work, but humans still own strategy, risk, refresh decisions, and authority building.

Pipeline Part Good Automation Manual or Guarded Decision Why
Site context ingestion. Build a site context profile from existing pages, brand language, niche, audience, products, services, entities, and content style. Human confirms the business model, forbidden claims, tone, ICP, and commercial priorities. Prevents generic AI content that could belong to any site.
SERP-driven briefing. Analyze ranking pages, headings, entities, answer formats, SERP features, media, schema, and intent patterns before writing. Human checks whether the SERP is the right target and whether copying the current SERP shape would miss the business angle. The brief should match what the query needs, not what the model imagines.
Structured generation. Generate against an approved brief with planned headings, internal links, page type, CTA, proof requirements, and source requirements. Human or SME reviews facts, claims, examples, brand fit, legal risk, and user usefulness before publication on important pages. Content quality is not only grammar. It is accuracy, intent fit, proof, and trust.
CMS publishing. Publish approved content with category, taxonomy, slug, title, meta description, canonical, schema, images, internal links, and CTA fields. Auto-publish only after strict QA exists. High-risk niches, money pages, YMYL pages, and client-sensitive pages need review before going live. The gap between draft and live page is where many pipelines break.
Post-publish contract. After publish, fetch the public URL and verify status code, title, H1, canonical, robots, indexability, schema parse, main content marker, internal links, images, and primary CTA. Fail closed for missing H1, wrong canonical, noindex, empty main content, broken template, missing CTA, or wrong page marker. A CMS success response is not proof that the public page rendered correctly.
Cache and rendering verification. Check immediately, then repeat after cache/CDN/ISR settles. Use two consecutive matching checks or a short timeout instead of one blind sleep. Rollback only when the previous public artifact is known-good and the rollback path is tested. Otherwise alert, freeze next publish, and repair. Some failures appear after cache convergence, plugin filters, or delayed rendering.
Keyword and cluster strategy. Score opportunities from GSC, SERP, competitors, internal search, support questions, and revenue/page-type value. Human chooses which clusters to prioritize based on business goals, authority ceiling, funnel needs, and topical map. An agent can execute any keyword list, including a bad one.
Refresh and rewrite decisions. Find pages stuck in positions 8 to 20, pages with rising impressions but low CTR, pages with query drift, and pages with old facts. Do not automatically rewrite every page that stalls. Review whether it needs snippet work, internal links, answer completeness, consolidation, or waiting. Some pages recover or break through without a rewrite. A bad refresh can kill a page.
Content economics and retirement. Classify pages by stage: not indexed, indexed with no impressions, impressions with weak CTR, visits with no CTA action, CTA actions with no revenue. Retire only after enough evidence. Prefer hold, refresh, merge, or redirect before delete. Use revenue only after enough qualified traffic exists. Zero revenue from low sample size is not proof that the topic has no value.
Backlinks and authority. Find prospects, unlinked mentions, digital PR angles, HARO-style requests, partner pages, guest post opportunities, and topical overlap. Human approves link targets, pitches, and risk. Do not automate paid link schemes or bulk outreach. Content can compound, but authority often becomes the ceiling.
Maintenance burden. Monitor prompts, API changes, CMS integration errors, plugin changes, schema validation, feed changes, and reporting drift. Assign maintenance time. A homemade pipeline without upkeep will decay. Agentic SEO is an operating system, not a one-time script.
  • Best condition: the pipeline can produce, publish, verify, monitor, and report, while humans still control strategy, risky actions, source truth, link acquisition, and business priority.
  • One steady publishing rhythm can be better than bursts, but consistency does not excuse weak pages. Quality, intent, crawlability, and maintenance still matter.
  • Measure beyond GSC when a real product funnel exists. Track CTA clicks, form starts, signups, trials, activated accounts, qualified leads, assisted conversions, and revenue by landing page where possible.
  • For content sites where clicks proxy revenue, GSC can guide prioritization. For service, SaaS, ecommerce, or lead-gen sites, GSC is diagnostic data, not the final objective.
  • Myth: a production agentic SEO pipeline means full autopilot. Reality: the safest systems automate repeatable checks and execution, then fail closed or ask for review when the action can affect ranking, revenue, compliance, or trust.

SEO Agent Production Design Rule

Use this before building or approving an SEO agent that will touch real websites, clients, reports, CMS content, repositories, or revenue workflows. Most agent failures are not model failures first. They are scope, context, workflow, and ownership failures.

Design Area Required Rule Failure If Missing
Human workflow mapping. Write the exact human process for the most common SEO tasks before automating: tools opened, fields checked, decisions made, outputs created, and escalation cases. The agent produces the visible output but misses hidden work such as CRM notes, approvals, QA, reporting, or escalation.
Shared definitions. Define terms such as audit, optimize, publish, refresh, fix, approve, revenue, lead, and done. Developer, SEO, product owner, and client use the same words for different expectations.
Persona, tools, skills, and limits. Give the agent a role, allowed tools, forbidden actions, data sources, task boundaries, edge cases, and acceptance criteria. The agent guesses scope, uses weak sources, or takes actions it should only recommend.
Decision boundaries. Separate actions the agent can do, actions it can draft, and actions that require human approval. Unreviewed changes affect rankings, client trust, redirects, indexation, schema, outreach, or revenue pages.
Step-level model choice. Use cheaper/simple models or deterministic scripts for extraction, formatting, classification, and routine checks. Use stronger models for complex reasoning, synthesis, and strategy drafts. Costs spiral, speed drops, and the system becomes too expensive to keep running.
Monitoring and audit trail. Log inputs, outputs, sources, tool calls, costs, changed URLs/files, approvals, errors, and rollback status. Silent failures occur and no one can explain what the agent did or why users/results changed.
Budget and risk caps. Set token/API budgets, page limits, publishing limits, outreach limits, crawl limits, and stop conditions. The agent over-produces, burns budget, sends bad outreach, or changes too many pages before review.
Revenue validation. Define how the agent's work connects to qualified traffic, lead quality, calls, signups, sales, retention, or operational time saved. The system looks productive but does not move a business metric.
  • Build the agent around the user's pain point and the business workflow, not around the novelty of agent frameworks.
  • If the agent cannot explain what it changed, what source it used, and what KPI should move, the system is not production-ready.
  • Myth: AI will figure out the workflow. Reality: the workflow must be explicit before the agent can execute it reliably.

Agentic Content Tree and Internal Link Rule

Use this when an agent is creating or improving many pages. The information structure must be designed before copy is generated. The agent should not create pages only because a keyword exists, and it should not internally link only because two pages are siblings.

Decision Rule Guardrail Why
New page or existing page. If the keyword group logically belongs to an existing page, merge or add it there. If it does not belong to any existing group, create a new page only when it has clear standalone intent. Human reviews keyword groups before publishing at scale. Prevents cannibalization, duplicate pages, and thin programmatic expansion.
Keyword group size. Keep keyword groups focused. A page can have a small group if that is the cleanest intent match. Do not force a large fixed keyword count. As a practical ceiling, review pages with more than about 10 to 12 grouped keywords unless they clearly share one intent. Contextual logic is more important than keyword quantity.
Hub and sub-hub structure. Create hubs and sub-hubs from product, service, entity, audience, use case, support, and guide logic before generating page copy. The agent may propose the structure, but a human should approve the tree before scaled production. The page only makes sense if its place in the content tree makes sense.
Content blocks. Generate pages from approved blocks such as hero, comparison, steps, FAQs, proof, CTA, table, media, related pages, and examples, each with rules and limits. Do not let the LLM invent random sections. Each block must support the page intent. Structured generation is easier to QA than free-form AI writing.
Contextual internal links. Link root pages to hubs, hubs to sub-hubs, sub-hubs to support pages, and leaf pages to genuinely related pages. Use semantic relevance, not only folder position. Limit link count and require a reason for every link. Avoid linking to every sibling page by default. Internal links should help users and search systems understand relationship and priority.
Cross-branch links. Allow links across different branches when the relationship is useful, such as tool to project, material to service, product to guide, or problem to solution. Use vector search, tags, entity matching, or manual rules only as suggestion systems. Final links must still make sense in context. Useful relationships often exist outside a neat parent-child tree.
Indexing push. Use clean crawl paths, sitemap, internal links, and GSC inspection/request indexing for important discovered-not-indexed pages when appropriate. Do not treat manual indexing requests as a substitute for page quality, crawlability, internal links, or authority. Indexing requests can help discovery, but they do not make weak pages worth indexing.
Existing poor pages. When old pages have weak results, keep the useful keyword group if it still matches intent and rebuild the page structure/content around it. Compare before/after performance and annotate every major rewrite. Improving existing pages is often safer than creating more pages.
  • Before generating copy, require: product or business context, page keyword group, page metadata, content block list, internal-link rules, media rules, and page acceptance criteria.
  • Agentic SEO can work without strong backlinks in low-competition or underserved niches, but do not generalize that result to every market. Competition, country, language, authority, and product demand change the outcome.
  • Ignore spam backlinks and seller-generated links when judging authority. Third-party backlink counts can include worthless links.
  • Traffic graphs are not enough proof. Always ask whether traffic is targeted, whether users engage, and whether the traffic produces leads, signups, sales, or another business outcome.
  • Myth: agentic SEO is just writing good content at scale. Reality: the hard part is information structure, page grouping, contextual internal links, QA gates, measurement, and continuous improvement.

AI-Built Website Launch and Ranking Rule

Use this when a site is built mostly with Claude, ChatGPT, Codex, Cursor, or another AI coding workflow and the owner wants indexing, rankings, organic traffic, or AI citations. AI can speed up build and content production, but SEO success still depends on page selection, keyword clustering, technical setup, useful data, validation, and patient testing.

Area What Can Work What Can Fail Rule
Tool websites. Launch a complete useful tool with crawlable landing pages, clear metadata, examples, internal links, schema when accurate, and a clean sitemap. Only launching an app shell with no crawlable context, no examples, no use cases, and no internal links. Build the tool and the SEO surface together.
Programmatic SEO or directories. Launch in batches when the data is accurate, validated, useful, and template quality is proven. Publishing generic AI pages in bulk with weak data, duplicated text, or no user value. Validate data first, publish controlled batches, then monitor indexation and impressions.
Keyword research and topical clustering. Use a parent topic/category for the homepage or hub, then create useful subpages for related cluster intents. Creating pages only because a keyword exists, without clear parent-child structure or internal links. Cluster before building pages.
Exact-match domains. Can help with clarity or local/niche relevance when the site still has useful pages and real value. Assuming an EMD ranks by itself or choosing it over long-term brand trust when the project needs a real brand. Treat EMD as optional positioning, not the strategy.
AI-generated metadata and schema. AI can draft titles, meta descriptions, WebApplication, HowTo, FAQ, Product, LocalBusiness, or other schema where accurate. Invalid, generic, misleading, or page-type-mismatched markup. Validate schema and check metadata against actual page intent.
Early link and DR work. Relevant directories, social profiles, Product Hunt-style launches, niche mentions, and quality backlinks can support discovery. Chasing DR, buying weak links, or building spam links before the product, structure, and content are strong. Do not optimize third-party authority scores as the goal.
Post-launch changes. Wait for enough crawl and impression data unless there is a technical emergency. Changing titles, templates, content, URLs, and internal links every few days before Google can evaluate the site. Monitor first, then change gradually and annotate every change.
  • Pre-launch checklist: crawlable 200 pages, unique title/H1, meta description, canonical, sitemap, robots, internal links, schema where useful, analytics, GSC/Bing setup, mobile UX, CWV basics, forms, and conversion tracking.
  • Useful AI workflow: use GSC, SERP data, crawl data, Ahrefs/Semrush when available, Google Maps for local, Reddit/forums for language, and live-page checks as inputs. Do not let AI invent the evidence.
  • For pSEO, define data source, validation rules, duplicate checks, empty-page handling, internal-link modules, sample QA, and publish batches before scaling.
  • For local AI-built sites, exact-match or location domains can work for rank-and-rent style tests, but a real brand should usually use brandable naming and stronger trust signals.
  • Myth: AI-built sites rank because AI built them. Reality: they rank when the SEO fundamentals, useful page types, technical access, data quality, internal links, and intent match are strong.
  • Myth: screenshots or private domain claims prove a method. Reality: require evidence such as GSC trends, URL examples, page structure, search intent, crawlability, and whether results held over time.

App and Tool Myth Busting

Myth Reality Better Rule
If the tool is useful, Google will rank it. Google still needs crawlable context, links, authority, clear intent, and index-worthy content. Build a useful landing page around the tool, not just the tool interface.
Blocking iframes will make the original rank again. Iframe blocking is a security/distribution choice, not an indexing fix by itself. Fix indexing, content context, canonical signals, and attribution first.
Every tool needs a blog first. Some tools need search-intent landing pages, examples, templates, galleries, or output pages before a blog. Match the content type to how users search for the tool outcome.

Content Inventory Stop-or-Scale Rule

Use this when a site already has many pages or posts and the next question is whether to keep publishing, refresh, consolidate, prune, or pause.

Signal Meaning Action
Pages are indexed, earning impressions, and supporting a cluster. The content system is working. Scale carefully into adjacent intents and strengthen internal links.
Pages are indexed but get no impressions, clicks, links, or conversions. They may have weak demand, poor targeting, duplicate intent, or low authority. Improve, merge, redirect, noindex, or remove based on page value and evidence.
Many pages are discovered or crawled but not indexed. Google may not see enough value, uniqueness, internal importance, or crawl priority. Pause similar publishing and audit templates, duplication, internal links, quality, and sitemap strategy.
Many pages overlap the same intent. The site may create cannibalization and thin topical fragmentation. Consolidate into stronger pages and map supporting sections clearly.
Content team cannot update or QA the volume. The site is creating maintenance debt. Reduce publishing pace and create refresh, ownership, and pruning rules.
  • Content volume becomes too much when the marginal new page is weaker than improving an existing page.
  • After core topics are covered, spend more time reoptimizing winners and consolidating weak overlap instead of publishing random new posts.
  • Do not prune blindly. Use GSC, GA4, crawl data, backlinks, conversions, and business value before removing or noindexing pages.

Weak, Outdated, or Low-Traction Article Decision Rule

Use this when deciding whether to improve, merge, noindex, delete, 404, 410, or 301 old articles, event posts, press releases, promotional posts, expired pages, thin pages, or low-traffic blog content. Do not use one blanket rule for thousands of URLs.

Page Condition Best Action Why Before Action
Gets impressions, clicks, conversions, image traffic, or ranks for useful queries. Improve and keep indexable. The page already has search or business evidence. Check GSC page/query data, GA4 landing page data, current SERP, internal links, and freshness.
Ranks around positions 6 to 25 or has impressions for relevant topics. Refresh, expand, improve title/snippet, add proof, and strengthen internal links. It may be a near-win page worth improving before creating new content. Confirm the query still matches business goals and search intent.
Several weak pages cover the same topic. Consolidate into one stronger page and 301 the weaker URLs to the most relevant surviving page. Combines topical value, backlinks, and internal-link signals instead of fragmenting them. Map all old URLs, backlinks, internal links, rankings, and best target page.
No traffic, no impressions, no backlinks, no conversions, no image value, and no future usefulness. Remove and let it 404 or return 410. Keeping useless pages creates maintenance overhead. Remove internal links and sitemap references. Do not redirect to unrelated pages.
No traffic, but has relevant backlinks or external references. 301 to the most relevant live page, or improve the original page if it still has a useful purpose. Relevant links may still have value. Irrelevant redirects are not useful. Check backlink relevance, anchor text, link quality, and closest matching target.
Expired event, old promotion, outdated press release, or dated announcement. Keep only if it has archival, image, link, brand, or historical value. Otherwise 410/404 or redirect to a relevant evergreen event/category page. Old event posts often lose usefulness after the date passes, especially if duplicated across many sites. Check backlinks, image search traffic, social referrals, and whether a current evergreen replacement exists.
Useful for users but not intended for search. Noindex and keep accessible. Noindex is for pages that should exist for users but should not appear in search. Examples: internal search pages, filter pages, thank-you pages, account pages, temporary rewrite queues, or utility pages.

Content Pruning Work Order

  1. Export URL-level data from GSC for the last 6 to 16 months: clicks, impressions, CTR, position, page, query, and search appearance where available.
  2. Export GA4 landing page data: sessions, conversions, engagement, revenue, assisted conversions, and channel mix.
  3. Check backlinks in GSC, Ahrefs, SEMrush, or available link tools. Mark relevant links separately from junk links.
  4. Check internal links pointing to the page and remove or update them before deleting or redirecting.
  5. Check image search value before deleting articles with indexed images, especially old news, sports, event, recipe, product, or visual content.
  6. Tag each URL: keep, improve, merge, 301, noindex, 404, 410, or hold for manual review.
  7. Update sitemap, internal links, canonical tags, redirects, and category/tag archives after the cleanup.
  8. Monitor GSC indexing, crawl stats, impressions, and traffic after cleanup. Do not judge the result from one day of data.

Noindex, Delete, Redirect, and 404 Myth Busting

Myth Reality Rule
Noindexing all weak content is the safest fix. Noindex keeps pages alive and may still create crawl, maintenance, and user-path overhead. Use noindex when the page should exist for users but not search, not as the default hiding place for bad content.
Too many 404 pages automatically hurt rankings. 404s and 410s are normal when pages are genuinely gone. The problem is broken internal links, deleting valuable pages, or redirecting irrelevant pages. Let useless deleted pages return 404/410. Fix internal links and sitemap references.
Every deleted page should redirect to the homepage. Irrelevant mass redirects can confuse users and search engines. 301 only to the most relevant replacement. If no relevant replacement exists, 404 or 410 is cleaner.
Thin means low word count. Short content can be useful. Long content can be useless. Usefulness depends on intent, value, and context. Judge the page by whether it satisfies a real user/search/business need, not by word count.
AI answers about SEO cleanup can be trusted directly. AI may repeat common SEO myths from the web. Use GSC, live crawl data, official documentation, and page-level evidence before acting.

Programmatic and Templated Page Decision Rule

Use this before creating many pages from one template. Programmatic SEO can work when pages are data-rich and useful. It becomes scaled low-quality content when pages exist mainly to catch keyword variations.

Gate Pass Condition Fail Condition Decision
Distinct intent The page answers a different buyer, location, product, model, use case, or comparison need. The page only swaps a keyword, city, make, model, or adjective. Create only if intent is distinct.
Unique data The page has real inventory, prices, availability, reviews, staff, local proof, specs, examples, or first-party data. The page has generic rewritten copy with no new facts. Hold, merge, noindex, or enrich before publishing.
Useful template The template helps users decide, compare, book, buy, call, or understand the next step. The template is just paragraphs built around keywords. Improve template before scaling pages.
Quality control There is automated validation and human spot-checking for facts, duplicate text, broken links, indexability, and page usefulness. Pages are generated or written at volume without checks. Do not scale until QA exists.
  • Use automation for repetitive structure, data insertion, internal links, and QA. Use human judgment for page selection, positioning, examples, proof, and final publish decisions.
  • If the writer has no GSC or analytics access, the SEO owner must provide the intent, target query group, page role, internal-link plan, and success metric in the brief.
  • Do not make writers operate as blind endpoints. The strategic value is deciding what is worth publishing, why it should exist, and how it is different.

Thin Page Intent and Entity Context Rule

Use this when a page is short but may still answer the user's intent, or when the proposed fix is creating a second near-duplicate page only to target a keyword variation. Thinness is not only character count. A page is weak when it lacks the context, data, proof, or usefulness needed for the intent.

Condition Do Do Not Why
One page covers "games like X" and "similar games to X". Keep one strong page if the intent is the same. Create duplicate pages only because the wording changes from "like" to "similar". Search engines understand close intent variants. Duplicating pages splits value and creates cleanup work.
Page has little prose but strong structured comparison data. Judge whether the data answers the task. Add concise context where needed. Add filler paragraphs only to increase word count. Useful tables, classifications, examples, and relationships can satisfy intent better than long generic copy.
Similar-item recommendation lacks explanation. Add "why similar" classifications such as genre, mechanics, difficulty, audience, setting, features, price, platform, or use case. List related items without explaining the relationship. The context around entities is what helps users and search engines understand the recommendation.
Traffic comes only from brand or item-name queries. Check whether the page actually answers non-brand discovery intent and whether internal links expose that intent. Assume adding keywords to the title will create discovery demand. Long-tail discovery needs page value, classifications, internal links, and query-fit, not only keyword swaps.
  • For recommendation, comparison, or similar-item pages, organize by why the match exists: features, audience, category, problem, style, constraints, or decision criteria.
  • If one page can satisfy multiple close intents clearly, keep one stronger page instead of many thin variants.
  • Create separate pages only when the user task, data set, and page value are materially different.
  • Myth: a page must be long to avoid being thin. Reality: a short page can work if the data and structure fully answer the intent.

Directory and Local Marketplace Scale Rule

Use this when a directory, marketplace, contractor directory, local profile site, permit directory, job board, listing site, or database site already has thousands of indexed pages but traffic, links, or leads are growing slowly. At this stage, more pages are usually not the next best move unless the existing pages are differentiated and earning signals.

Focus Area What to Check Action Why
GSC index quality Indexed count, discovered not crawled, crawled currently not indexed, impressions, page 2 queries, low CTR pages. If "crawled currently not indexed" grows faster than indexed pages or important pages lose indexation, stop publishing similar pages and fix differentiation. For directories, index buckets are a useful quality and crawl-priority signal.
Profile differentiation Compare two profile pages from different cities or categories. If only name, city, and filler change, add real unique data: services, certifications, reviews, photos, service area, project examples, response time, license data, insurance, local details, and verified business facts. More words do not fix sameness. Page-specific facts do.
Data freshness Closed businesses, changed phone numbers, broken URLs, stale reviews, outdated services, old license status, old storm/permit data. Create a monthly re-verification process for top cities, top categories, and pages with impressions. Directories decay when listings become stale.
Lead capture and claim flow Claim profile flow, quote request flow, contractor signup, consumer lead form, call tracking, email capture, conversion rate. Improve forms, CTAs, confirmation emails, CRM routing, spam filtering, and profile-owner onboarding before chasing raw traffic. A small amount of qualified traffic can be valuable if the directory captures the lead.
Authority assets Storm reports, insurance data, cost data, permit data, calculators, rankings, local statistics, trend reports, maps, and comparison tools. Create citable assets that journalists, competitors, local sites, and contractors may reference. Being citable can earn better links than cold outreach.
Editorial pages Best roofers in city, cost guides, storm repair guides, contractor comparison pages, insurance explainers, local permit guides. Prioritize pages with real SERP demand, strong data, useful methodology, and links to relevant profiles. Editorial pages can bridge template pages, authority, and user decision-making.

Directory Growth Work Order

Reality: modern search systems understand page text and context much better than old keyword matching.

17. Content Quality and E-E-A-T Rules

Content must be useful for the visitor and aligned with the page purpose. Do not add unnecessary FAQs, sections, or keywords just to make a page longer.

Helpful Content Requirements

  • Answer the main intent completely without hiding the answer.
  • Write for what the intent is asking. Do not answer a different intent just because it is easier, longer, or has more keywords.
  • If the query is commercial, make the page commercial enough. If the query is informational, teach clearly before selling. If the query is comparison, compare honestly. If the query is local, show location relevance and proof.
  • Add original value, first-hand detail, examples, proof, process, data, visuals, tools, or expert review.
  • Make the page clearly about one primary topic.
  • Match the buyer or reader journey.
  • Use clear title, H1, headings, readable sections, and internal links.
  • Keep important text visible in the HTML and accessible to users and crawlers.
  • Update or remove outdated content.
  • Do not create mass low-quality pages with thin rewritten content.

Content Quality Measurement Beyond Traffic Rule

Use this when evaluating whether content is actually good, not only whether it currently ranks or gets traffic. Content quality should be measured by intent resolution, relevant visibility, user action, trust signals, and business movement.

Quality Layer What to Measure How to Interpret
Intent resolution. Does the page answer the specific query or task quickly and completely? Fast resolution can be good. Do not assume shorter time on page is bad if the user got the answer and moved forward.
Relevant query coverage. GSC impressions and queries for the target topic plus close variations. If queries are relevant, the page is being understood. If queries are irrelevant, the content may be unclear or misaligned.
Engagement behavior. Scroll depth, engaged sessions, internal link clicks, CTA clicks, video plays, downloads, tool use, return visits, and page path. Use behavior as evidence of usefulness, but always interpret it by intent and page type.
Conversion and demand waterfall. Visitor to lead, qualified lead, trial, demo, distributor click, signup, sale, booking, support resolution, or other business step. The right conversion depends on the page role. A support page may reduce tickets instead of creating leads.
Trust and authority signals. Natural links, brand mentions, social shares, quote-retweets, citations, expert references, customer feedback, and sales/support mentions. Good content often earns references or gets reused in real conversations, even before rankings peak.
AI search evidence. Brand mentions, source citations, cited wording, answer accuracy, and competitor comparison in AI-generated answers. Track as directional evidence. AI citations matter only if they are accurate and tied to useful business or trust outcomes.
Pre-publish QA. AI-assisted review against brief, E-E-A-T requirements, factual accuracy, source support, intent fit, and missing proof. Pre-publish checks reduce weak content, but they do not replace post-publish performance evidence.
  • Do not use pageviews alone as a quality score. A high-traffic page can be low quality if it attracts the wrong intent or converts nothing.
  • Do not use time on page alone as a quality score. Some excellent pages answer the question quickly and send the user to the next step.
  • Best quality read: relevant query coverage plus intent satisfaction plus meaningful user action plus trust signals plus business outcome.
  • Myth: rankings and traffic prove content quality. Reality: they prove visibility; quality must also be checked against user intent, useful action, trust, and business impact.

Content Brief and AI Outline Rule

Use this before writing any page that needs to rank, convert, protect revenue, support topical authority, or recover lost visibility. AI can replace some brief mechanics, but it must not replace the purpose of the brief.

Brief Item AI Can Help With Human or SEO Owner Must Decide
SERP and competitor extraction. Collect top-ranking headings, People Also Ask style questions, repeated entities, common formats, source patterns, and content gaps. Which SERP patterns matter, which are noise, and which competitor approach is worth beating or avoiding.
Outline creation. Draft a heading blueprint, suggest sections, group questions, and organize notes. The final page purpose, search intent, user stage, page type, business value, and exact promise of the page.
Trust and E-E-A-T planning. List possible proof points, source needs, author/reviewer fields, examples, definitions, data, screenshots, or expert notes. Why this page deserves trust over what is already ranking, what real evidence exists, and who is accountable for accuracy.
Internal linking and conversion path. Suggest relevant supporting pages, money pages, product pages, service pages, glossary pages, or comparison pages. Which links genuinely help the user move forward, which page should receive authority, and what conversion action is appropriate.
Paid content tools such as Surfer, Frase, Clearscope, or similar tools. Speed up SERP comparison, term/entity discovery, gap spotting, brief formatting, and workflow handoff. Whether tool recommendations fit intent. Do not obey suggested word count, keyword frequency, or headings if they create stuffing, fluff, or a different intent.

Content Brief Acceptance Checklist

  1. State the target topic, query group, or problem clearly.
  2. Define the page type: service page, location page, product page, category or collection page, comparison page, blog, guide, glossary, tool, directory, or support page.
  3. Confirm the search intent and what the user must get from the page.
  4. List the target audience, buyer or reader stage, and main decision the page supports.
  5. Summarize the SERP pattern: ranking page types, dominant format, repeated questions, rich result opportunities, and obvious gaps.
  6. Define the unique angle, proof, data, examples, process, product detail, service detail, or local detail that makes the page better than generic competitors.
  7. Provide a heading blueprint. The outline is a structure, not copied competitor content.
  8. List required sources, screenshots, quotes, SME notes, author/reviewer requirements, and facts that must be verified.
  9. List internal links, external references, media needs, schema opportunities, CTA, and conversion path.
  10. List what must not be included: irrelevant FAQs, copied headings, filler sections, unsupported claims, fake author details, or keywords outside the intent.
  11. Set success measurement: rankings, impressions, clicks, CTR, conversions, assisted conversions, engagement, indexation, or AI mention/citation visibility where relevant.

AI Overview and GEO Brief Add-On

  • If the query commonly triggers AI Overviews or answer summaries, add extractable answer blocks: short definitions, step lists, comparison tables, named facts, clear entities, and sourced claims.
  • For GEO, meaning Generative Engine Optimization, the goal is not only ranking in blue links. The goal is making content clear, factual, authoritative, and easy for AI systems to quote or cite.
  • Do not chase AI citations by making shallow summary content. The page must still satisfy the original user intent and business goal.
  • Use first-party data, expert explanation, product or service specifics, real examples, original visuals, citations, and consistent entity names to increase quote-worthiness.
  • Treat AI mention tracking as directional evidence unless the tool has a transparent method, consistent query set, country/device settings, and repeatable history.

Content Brief Myth Busting

  • Myth: an AI outline is the same as a content brief. Reality: an outline is only structure. A brief decides purpose, intent, proof, trust, differentiation, and success criteria.
  • Myth: paid content tools replace judgment. Reality: they help collect patterns, but they can also push average SERP mimicry, bloated word counts, and keyword stuffing.
  • Myth: briefs are unnecessary bureaucracy. Reality: for important ranking or conversion pages, the brief prevents wrong intent, generic writing, missing proof, and expensive rewrites.
  • Myth: AI should be ignored. Reality: AI is useful for extraction, grouping, drafting, and QA, but final strategy must be validated by search intent, business value, and evidence.

AI-Assisted Copywriter Submission Gate

Use this when writers, agencies, or AI-assisted workflows produce critical content. AI can support research, briefs, outlines, and editing, but final content must pass intent, accuracy, voice, usefulness, and evidence checks before SEO implementation.

Problem Signal Why It Is Bad Required Action
Longer than needed, repetitive, or padded by 800 to 1,500 words. Length does not equal usefulness. Extra text can bury the answer and weaken conversion. Cut to the intent. Keep only sections that answer the brief, support conversion, or add proof.

Competitor AI Content Flood Defense Rule

Use this when a competitor publishes many AI-written articles and takes rankings from an older site. Do not copy their volume blindly and do not assume Google will automatically remove them soon.

  1. Take a representative sample of lost queries and group by topic cluster.
  2. Compare the replacing URLs: intent, format, freshness, completeness, internal links, topical coverage, authority, backlinks, and SERP features.
  3. Ask why Google currently prefers those pages for those searches, not whether they were AI-written.
  4. Update a small number of high-value pages first with original evidence, clearer answers, examples, comparison tables, first-hand data, better structure, and stronger internal links.
  5. Consolidate overlapping or thin old pages before creating hundreds of new pages.
  6. Measure query cluster recovery before scaling the response.

Decision rule: defend with evidence, freshness, proof, and architecture. Do not fight an AI content flood with an unmeasured AI content flood.

Practical E-E-A-T Signals

  • Real author or expert reviewer with relevant credentials.
  • Author page and author box with role, background, social or professional profile, and topic relevance.
  • Original insights, first-hand experience, screenshots, examples, case studies, test results, data, or expert quotes.
  • Clear references and citations without copying source content.
  • Company history, real contact details, reviews, awards, certifications, memberships, licenses, policies, and third-party proof where relevant.
  • For ecommerce: verified product reviews, clear product information, trust badges backed by real third parties, company review profile, helpful category content, and complete schema.
  • Clean backlink profile and trusted external mentions.

No-Copy Rule

References are used to support accuracy. They are not content to copy. If a source helps the page, cite or mention it appropriately, then add original explanation, experience, examples, or analysis.

Authority vs Relevance Rule

Strong author pages, team credentials, publications, and expert bios improve relevance and trust signals. They do not replace external authority. External authority usually comes from third-party mentions, citations, links, reviews, press, memberships, partnerships, and independent references.

Signal What It Helps Limit
Team credentials and author bios Trust, expertise, reader confidence, YMYL credibility, content review. It is still self-published unless outside sources confirm it.
Peer-reviewed publications and professional profiles Expert proof and author verification. Must be relevant to the page topic and accurately represented.
Press releases Discovery, announcements, and possible journalist pickup. Press releases alone often carry limited authority, especially if paid, syndicated, or nofollow.
Independent editorial links and mentions Authority, prominence, trust, and referral discovery. Must be earned or legitimate. Do not buy manipulative links.

AI Content Rule

AI-assisted content is acceptable only when it is edited, fact-checked, useful, original, and aligned with the business. Do not publish scaled generic pages that exist mainly to manipulate rankings or AI answers.

Low-Quality AI Content and Tool Expansion Rule

Use this when a site wants to add many AI-generated tools, articles, templates, or pages quickly, especially on a website that already earns meaningful Google traffic.

Situation Risk Better Action
Hundreds of AI-generated pages or tools added in a short burst. Scaled low-value content, thin pages, poor QA, crawl waste, trust risk, and possible site-wide quality reassessment. Start small. Publish a limited batch, measure indexation, engagement, conversions, and quality before scaling.
Tools are useful but text is low quality. The tool may help users, but low-quality surrounding content can still reduce page value. Write useful support content: what the tool does, who it helps, examples, limits, FAQ, and real use cases.
Experiment could risk current revenue. High-traffic sites should not be used as reckless SEO experiments. Test on low-stakes sections or separate test properties first. Move only proven useful patterns to the main site.
Pages will not rely on Google traffic. Even if Google traffic is not the goal, indexable low-quality pages can still affect crawl and perceived quality. Keep non-search experiments noindexed or blocked appropriately, or host separately if the risk is not worth it.

AI Content QA Workflow

  • Use AI as a helper, not the final authority.
  • Brief first: define intent, audience, facts, sources, exclusions, examples, and required claims.
  • Draft second: mark missing facts as [needs source] instead of inventing.
  • Audit for slop: repeated phrases, generic advice, unsupported numbers, fake specificity, uniform bullet lists, keyword stuffing, and restatement loops.

Technical SEO Mental Model Rule

Use this when crawling, rendering, indexing, canonicalization, and ranking are being mixed together. Treat them as connected stages, not one single process.

Stage What It Means Common Failure How to Check
Crawl. Search engines discover and fetch a URL. Blocked by robots.txt, broken internal links, bad status code, firewall, redirect loop, server error, or unreachable sitemap. Crawl tool, server logs, GSC Crawl Stats, URL Inspection, robots.txt, sitemap, and HTTP status.
Render. Google processes HTML, CSS, JavaScript, and page resources to understand visible content and links. Main content or links appear only after blocked, delayed, broken, or heavy JavaScript. Rendered HTML, URL Inspection screenshot, browser dev tools, mobile test, and crawl with JavaScript rendering.
Index. Google stores and understands an eligible page. Noindex, soft 404, low quality, duplicate selection, wrong canonical, thin page, or not enough discovery signals. GSC Page indexing, URL Inspection, site search, canonical report, source/rendered meta robots, and sitemap coverage.
Canonicalization. Google chooses the representative URL among duplicate or very similar URLs. Wrong preferred URL, conflicting signals, duplicate templates, parameter URLs, http/https conflicts, or blog-to-service canonical misuse. Declared canonical, Google-selected canonical, internal links, redirects, sitemap URLs, hreflang, and duplicate-content patterns.
Rank and serve. Google decides whether and where an indexed page should appear for a query. The page is indexable but does not satisfy intent, lacks authority, lacks proof, has weak UX, or is beaten by better competitors. GSC query/page data, SERP intent analysis, competitor pages, links, content quality, reviews, page experience, and conversion data.
  • Do not rewrite content before confirming the page can be crawled, rendered, indexed, and selected as the correct canonical URL.
  • Indexing does not guarantee ranking. Ranking analysis starts after eligibility and understanding are confirmed.
  • Rendering matters most when important content, links, metadata, schema, or CTAs depend on JavaScript.

Canonical Learning Rule

  • A canonical tag is a preferred-URL hint for duplicate or very similar pages. It is not a redirect, noindex, or guaranteed command.
  • Do not use canonical tags as a low-quality cleanup shortcut. Use improve, merge, redirect, noindex, delete, 404, or 410 based on the page's actual value and replacement path.
  • Do not canonicalize a useful informational blog to a transactional service page only to "pass value". Use internal links and clear page relationships instead.
  • If Google chooses a different canonical, inspect internal links, sitemap, redirects, content duplication, hreflang, pagination, parameters, and template duplication.
  • Myth: canonical fixes all duplicate or weak content. Reality: it only helps when the preferred URL signal matches what the content and site architecture are already saying.

INP and Main Thread Rule

Use this when Core Web Vitals show poor Interaction to Next Paint or users report slow clicks, taps, menus, filters, forms, checkout, booking, or interactive widgets. INP is about interaction responsiveness, not only initial page load.

Problem What It Means How to Improve
Input delay. The browser is busy before it can start handling the user's click, tap, or keypress. Reduce long tasks, defer non-critical scripts, break up JavaScript work, and limit third-party scripts.
Slow event handling. The event handler itself takes too long. Simplify handlers, avoid heavy synchronous work, move expensive work off the critical path, and cache repeated calculations.
Presentation delay. The browser handles the event but takes too long to show the visual result. Reduce DOM complexity, layout thrashing, heavy style recalculation, large component updates, and unnecessary re-renders.
Heavy JavaScript bundle or hydration. The page sends more client-side code than the interaction needs. Remove unused libraries, code-split, lazy-load below-the-fold widgets, use SSR/SSG where appropriate, and replace small library use with simple in-repo code when safe.
Third-party scripts block interaction. Ads, trackers, chat widgets, maps, booking widgets, or tag managers compete for the main thread. Audit each script, delay non-critical tags, remove unused vendors, and load heavy widgets only when needed.
  • First identify the slow interaction. Do not blindly compress images when the issue is click responsiveness.
  • Use field data when available and lab tools to reproduce the slow interaction. PageSpeed score alone is not the diagnosis.
  • AI can help refactor scripts or replace small libraries, but the fix must be tested in the actual browser and page flow.
  • Myth: INP is fixed only by reducing total page size. Reality: the main issue is often long tasks, event handlers, hydration, third-party scripts, or inefficient DOM updates.

Agentic Browsing Technical Rule

Use this when a site passes normal Lighthouse SEO, best practices, or performance checks but fails an "Agentic Browsing" check. Treat agentic browsing as experimental machine-interaction readiness, not a normal ranking factor or standard SEO score.

Check Area What It Means How to Improve
Agent-centric accessibility. Agents use the accessibility tree to understand and interact with the page. Use semantic HTML, clear button/link names, labels for form fields, valid ARIA, logical roles, and visible focus states.
Interactive stability. Agents can fail when buttons, forms, menus, or content shift while they interact. Reduce CLS, reserve space for media/ads/widgets, avoid late layout shifts, and test forms/menus on mobile.
Discoverability. Machine-readable summaries or tool declarations may help agents understand the site. Check whether the audit expects llms.txt, WebMCP, or another experimental feature. Do not add experimental systems blindly.
Forms and task flows. Agentic browsing is more relevant when an agent needs to complete a quote, booking, checkout, filter, or support task. Make forms simple, labeled, error messages clear, buttons descriptive, and required steps visible.
Audit result unclear. The score alone is not enough. Expand the audit details, copy the failing item text, inspect affected elements, then fix the specific issue.
  • P1 if agents or users must complete revenue-critical tasks such as booking, checkout, lead forms, account setup, or support flows.
  • P2 if the issue affects normal accessibility, forms, buttons, or layout stability.
  • P3 if it is only an experimental llms.txt or WebMCP readiness item with no current business use case.
  • Myth: agentic browsing failure means SEO is broken. Reality: it may indicate accessibility, interaction, stability, or experimental agent-readiness issues, not classic indexation or ranking failure.

Indexing and Crawlability

  • Check status code, robots.txt, meta robots, x-robots-tag, canonical, sitemap inclusion, internal links, redirect chains, and blocked resources.
  • Use Search Console URL Inspection when available to see how Google sees the page.
  • Remember that robots.txt blocks crawling, not guaranteed indexing removal. Use noindex or removal tools for index control when appropriate.
  • For excluded or unindexed pages, classify the reason before recommending fixes.

XML Sitemap and Internal Link Priority Rule

Use this when pages are submitted in XML sitemaps but still not indexed, crawled slowly, or treated as low importance. A sitemap helps discovery and reporting. It does not replace crawlable internal links, useful page quality, or site architecture.

Situation Best Interpretation Required Action
Important page is only in XML sitemap. Google can discover the URL, but the site is not showing that the page matters. Add crawlable internal links from relevant hubs, categories, navigation, related pages, breadcrumbs, or high-trust sections.
New pages are discovered slowly. The issue may be crawl path, site freshness, internal-link depth, weak hub structure, or low authority. Link new pages from active pages Google already crawls, update hubs, and submit clean sitemaps.
Large site has many URL types. Sitemaps are useful for segmentation and indexing intelligence. Create separate sitemaps by page type, country, language, template, or priority section so GSC data is actionable.
Sitemap contains redirected, noindexed, non-canonical, duplicate, or low-value URLs. The sitemap is sending weak or conflicting preference signals. Keep only canonical URLs that should be indexed. Remove junk, redirects, errors, blocked URLs, and temporary filter URLs.
  • Best condition: important pages are both internally linked and included in a clean sitemap.
  • Worst condition: important pages are orphaned and exist only in the sitemap.
  • Do not delete sitemaps because internal links matter more. Use both, but fix internal-link architecture first when importance is unclear.
  • Myth: XML sitemap submission means Google should index the page. Reality: sitemap discovery does not guarantee crawling, indexing, or ranking.

Location Parameter URL Indexing Rule

Use this when location, filter, or internal-search URLs are indexed, such as /search-results?keywords=Tokyo or /search-results?keywords=Ottawa. Do not answer yes or no only from the presence of a parameter. Decide by page value, control, duplication, crawl risk, and whether a better indexable URL exists.

Condition Index Decision Better Structure Why
Internal site search page with random queries, many combinations, thin results, empty results, or duplicate result sets. Usually noindex or prevent crawling where appropriate. Keep search usable for users but keep it out of indexable architecture. Internal search and faceted URLs can create crawl waste, duplicate pages, and low-value indexed URLs.
Location-specific job listings, product listings, or service listings have real demand and useful unique results. Can be indexable if controlled and valuable. Create clean permanent URLs such as /jobs/tokyo/, /careers/ottawa/, or /locations/tokyo-jobs/. Location landing pages can satisfy search intent better than generic search-result URLs.
Parameter URL is already ranking and driving qualified traffic. Do not noindex blindly. Plan migration to a clean permalink URL, then 301 the parameter URL to the matching page. Protect existing traffic while improving architecture.
Parameter URLs create infinite combinations or duplicate parameters. Do not allow uncontrolled indexing. Use crawl controls, canonical rules, noindex where crawlable, standard parameter separators, consistent filter order, and 404 for impossible combinations. Unbounded URL spaces can waste crawl and slow discovery of important pages.
International or regional listing pages exist. Index only the canonical regional pages that provide real value. Use self-canonicals, hreflang where appropriate, localized content, clean sitemaps, and internal links from regional hubs. Regional pages need clear geo and language signals, not only a parameter.
  • Audit before deciding: GSC page/query data, indexed count, non-indexed count, crawl volume, duplicate patterns, empty result pages, traffic value, conversions, and whether users search for those locations.
  • If the page is important, it should not look like an accidental internal-search result. Give it a stable URL, title, H1, intro copy, useful results, internal links, canonical, sitemap inclusion, and related-location links.
  • If no jobs/products/results exist for a location, do not index a thin empty page. Use a helpful 404, noindex, or alternative nearby-location experience based on the site model.
  • Myth: all parameter URLs are bad. Reality: uncontrolled parameter spaces are bad, but controlled location landing pages can be valuable when they satisfy real search intent.

Blog to Service Page Canonical Rule

Use this when someone suggests canonicalizing related blog posts to service pages. This is almost never the correct use of canonical tags unless the blog post is truly a duplicate or near-duplicate version of the service page.

Situation Canonical Decision Better Action Why
Blog post answers informational intent and service page targets transactional intent. Do not canonicalize the blog to the service page. Keep both indexable if both are useful. Add contextual internal links, CTA blocks, service cards, comparison sections, and next-step links from the blog to the service page. The pages serve different funnel stages. Canonicalizing can remove the blog from independent organic visibility without helping the service page.
Blog post is thin, outdated, or overlaps heavily with a better service page. Do not use canonical as the first fix. Improve, merge, redirect, noindex, or remove based on page value and evidence. Canonical is a duplicate/preferred-URL signal, not a cleanup shortcut for low-quality content.
Blog post and service page are genuinely duplicate or near-duplicate versions of the same content. Canonical may be appropriate. Canonicalize to the preferred URL or consolidate with a redirect if one page should fully replace the other. Canonical is meant to signal the preferred version among duplicate or substantially similar URLs.
Team wants to pass ranking power from blogs to service pages. Do not use canonical for this purpose. Use internal links, hub structure, breadcrumbs, related content modules, and conversion elements. Canonicals signal sameness, not support. Google may ignore incorrect canonicals or stop ranking the blog.
  • Blog pages are usually top-of-funnel or middle-of-funnel assets. Their job is to answer informational queries and move some users toward service pages.
  • Service pages are money pages. Their job is to satisfy commercial or transactional intent and convert users.
  • If a blog supports a service page, show the relationship through internal linking and page structure, not canonicalization.
  • Test only on low-risk pages if someone insists, and measure indexation, impressions, clicks, ranking URL, and service-page performance before and after.
  • Myth: canonicalizing blogs to service pages transfers SEO value safely. Reality: it can kill blog visibility, may be ignored, and usually does not solve service-page ranking problems.

Index-Control Status Code Rule

Use this when deciding between noindex, 301, 404, and 410. The goal is to send the clearest signal for the real page state, not to hide every weak page.

Option Use When Do Not Use When
Noindex The page should remain accessible to users but should not appear in search, such as internal search, filters, thank-you pages, utility pages, temporary rewrite queues, or private-ish support pages. The page has no user purpose and should simply be removed.
301 redirect There is a relevant replacement page, consolidation target, updated version, category page, evergreen page, or equivalent page. The target is unrelated, such as redirecting old event posts to the homepage only to avoid 404s.
404 not found The page is gone and may or may not return. This is normal for deleted pages. The page has valuable backlinks, traffic, or a clear relevant replacement.
410 gone The page is intentionally and permanently gone, such as expired spam, obsolete event pages, or removed content with no replacement. The page may return or has a better relevant replacement.
  • After deleting or redirecting URLs, update internal links, sitemap URLs, navigation, related posts, category pages, and important backlinks where possible.
  • Redirect chains are bad hygiene. Use one-hop redirects to the best target.
  • Crawl budget is usually not the main concern for small or medium sites. Broken user paths and deleting valuable pages are the bigger risk.

Robots.txt Unreachable but Browser Works

Use this when Search Console says robots.txt unreachable or sitemap has a general HTTP error, but the file opens fine in a normal browser.

A file being accessible to you does not prove it was accessible to Googlebot at crawl time. Google may postpone crawling if robots.txt is unreachable because it cannot confirm crawl rules.
Possible Cause How to Check Fix Priority
WAF, CDN, Cloudflare bot protection, or security rule blocks Googlebot. Check WAF/firewall events for Google ASN 15169, verified Googlebot IPs, bot fight mode, rate limits, managed challenges, and blocked requests to robots.txt and sitemap. Allow verified Googlebot and make robots.txt/sitemap bypass bot challenges and aggressive WAF rules. P0 if crawling is paused or sitemap cannot be read.
Server returns 429, 5xx, timeout, truncated response, or connection failure to Google. Check GSC Crawl Stats, server logs, uptime, response times, hosting load, and exact timestamps. Fix server capacity, caching, timeout, TLS, and response stability. P0 or P1 depending on scale.
DNS or routing issue. Check DNS health, nameservers, IPv4/IPv6, propagation, CDN routing, and GSC host status. Fix DNS configuration and ensure Google can resolve the host consistently. P0 if affecting crawl.
TLS or nonstandard response issue. Test SSL certificate chain, protocol support, redirects, headers, compression, and whether Googlebot gets a normal response. Fix certificate chain, TLS configuration, redirects, or WAF/header behavior. P1.
Robots.txt syntax/location mismatch. Confirm robots.txt is at the top-level host/protocol path, such as https://example.com/robots.txt, and sitemap URL is absolute. Use correct host, protocol, status code, and sitemap URL. Remember rules are host/protocol specific. P1.

Best result: robots.txt returns a stable 200, 404, or 410 response to Google. Worst result: repeated 429/5xx/timeout/connectivity failure, because Google may slow or stop crawling until robots.txt can be fetched.

Robots and Sitemap Myth Busting

  • Myth: if robots.txt opens in my browser, GSC must be wrong. Reality: Googlebot may receive a different response because of WAF, DNS, TLS, rate limiting, or timing.
  • Myth: 404 robots.txt is always bad. Reality: Google treats 404/410 for robots.txt as successful, meaning no robots file exists.
  • Myth: robots.txt removes pages from Google. Reality: robots.txt controls crawling, not guaranteed indexing removal. Use noindex or removal methods where appropriate.
  • Myth: sitemap accessible in browser means Google can read it. Reality: check GSC Sitemaps, URL Inspection, logs, and server response to Googlebot.

Large-Scale Spam Injection Recovery Rule

Use this when a hacked site, CMS, plugin, database, or server injected many spam pages and Google indexed or crawled them. Do not treat removal of spam URLs as full recovery until the vulnerability is closed and crawl/index signals stabilize.

Step Action Why Priority
1 Prove the compromise is closed: inspect CMS users, admin users, plugins, themes, mu-plugins, scheduled tasks, database rows, uploads, server files, logs, SFTP/hosting access, and WAF events. Deleting spam pages does not matter if the injection path still exists. P0.
2 Rotate passwords and keys for CMS, hosting, database, SFTP/SSH, API keys, admin email, and third-party access. Old credentials may allow reinfection. P0.
3 Sample spam URL patterns and confirm they return true 404 or 410, not 200, redirect, soft 404, blocked-by-robots, or thin placeholder pages. Google needs a clear permanent state for spam URLs. P0 or P1 depending on scale.
4 Remove spam patterns from sitemaps, internal links, search pages, feeds, tags, and navigation. Sitemaps and internal links should not keep asking Google to crawl spam URLs. P1.
5 Use the GSC Removals tool only for urgent temporary hiding of visible spam results. Removals are temporary. Permanent cleanup requires Google recrawling the URLs and seeing 404, 410, noindex, or corrected content. P1 when spam is visible in search.
6 Pick one or a few high-value clean pages, strengthen internal links to them, confirm clean templates, and request indexing only after they pass live inspection. Repeated indexing requests on many URLs do not rebuild trust or fix crawl/index quality. P1.
  • Use 410 for clearly gone spam patterns when implementation is safe. Use 404 when normal deletion is correct. Both can be valid when the response is clean and consistent.
  • Do not bulk-redirect hacked spam URLs to the homepage or an unrelated money page just to avoid 404s. Redirect only when there is a deliberate cleanup target and the destination choice will not create soft-404, relevance, tracking, or trust problems.
  • A clean sitemap helps discovery of valid URLs, but it does not delete hacked URLs already known to Google or Bing. Permanent cleanup requires fixed status codes, removed internal links, and recrawl.
  • Track recovery by crawl stats, indexed spam count, affected clean-page impressions, clean-page crawl dates, and query/page visibility. Do not report only "we submitted removals".
  • Recovery may take months after the site is genuinely clean, especially after very large spam footprints. Do not count recovery time from the day the SEO audit started if the hack was still open.
  • Myth: 410 alone fixes trust. Reality: 410 helps URL cleanup, but security, quality, internal links, and recrawl matter too.
  • Myth: GSC removals permanently deindex spam pages. Reality: removals hide results temporarily unless the underlying URL state is fixed.
  • Myth: "Crawled, currently not indexed" always means a penalty. Reality: it can mean quality, duplication, weak internal links, crawl priority, or post-spam reassessment.

Rendering and JavaScript

  • Check whether main content, links, product details, prices, reviews, and CTAs are available in rendered HTML.
  • If Google or another crawler cannot see key content that users see, fix rendering, server-side output, hydration, blocked resources, or link discoverability.
  • Do not hide different content from users and crawlers.

Internal Linking

  • Important pages must be linked from relevant hubs, navigation, related pages, breadcrumbs, or body content.
  • Use descriptive anchor text. Avoid generic anchors when context matters.
  • Money pages should receive stronger internal support than low-value blog pages.
  • For new pages, define where links will come from before publishing.
  • If an external backlink lands on a less-relevant page, add contextual internal links from that page to the best matching money, service, location, product, or category page.

Page Experience

  • Check Core Web Vitals, mobile display, HTTPS, intrusive interstitials, excessive ads, and main-content clarity.
  • Do not chase perfect scores for SEO alone. Improve issues that affect users, crawl, rendering, conversion, or competitive quality.

PageSpeed Insights Rule

Use PageSpeed Insights when speed, mobile UX, Core Web Vitals, performance, accessibility, or page experience is part of the issue.

Result Meaning Action Priority
Good field data for LCP, INP, and CLS. Real users generally have acceptable loading, interaction, and layout stability experience. Do not make this the main SEO task unless conversion or user experience still has visible problems.
Poor LCP. Main content loads too slowly. Prioritize on money pages, templates used by many pages, and pages with ranking or conversion loss. Check server response, hero image, render-blocking resources, font loading, and heavy scripts.
Poor INP. The page responds slowly to user interaction. Prioritize when forms, menus, filters, checkout, booking, or CTA interactions feel delayed. Check JavaScript, third-party scripts, long tasks, and interaction handlers.
Poor CLS. Page layout shifts while loading. Prioritize when CTAs, forms, product content, ads, banners, images, or headers move unexpectedly. Set image dimensions, reserve ad space, avoid late-injected layout changes.
No field data. The URL may not have enough Chrome real-user data. Use lab data as a diagnostic clue, not final proof. Also check GSC Core Web Vitals URL groups and manual mobile UX.

Best result: the page is fast enough for real users, stable on mobile, easy to use, and not blocked by heavy scripts. Worst result: a high-value page is slow, unstable, hard to interact with, or missing important content during rendering.

Core Web Vitals: What, When, Priority, and Myths

Metric What It Means When to Check Good and Bad Common Myth
LCP Largest Contentful Paint. It measures when the largest visible image, text block, or video in the first viewport renders. Check when a page feels slow, PageSpeed flags LCP, rankings or conversions drop on heavy templates, or hero content loads late. Good is 2.5 seconds or less for most visits. Poor is over 4 seconds. P1 for important money-page templates. Myth: lazy loading all images is always good. Reality: never lazy-load the likely LCP image or above-the-fold hero image.
INP Interaction to Next Paint. It measures how quickly the page visually responds after user interactions. Check when menus, filters, forms, booking, checkout, accordions, or CTAs feel delayed. Good interaction is fast and smooth. Poor INP is a P1 issue when it affects conversion actions. Myth: only load speed matters. Reality: a page can load fast but still feel broken if interactions are slow.
CLS Cumulative Layout Shift. It measures unexpected movement of visible page elements. Check when ads, images, banners, fonts, reviews, maps, forms, or CTAs move after loading. Good layout stays stable. Poor CLS is P1 when users misclick CTAs, forms, product elements, or navigation. Myth: layout shift is only design polish. Reality: it can hurt usability, trust, and conversion.

Lazy Loading Rule

  • Use lazy loading for below-the-fold images, galleries, maps, embeds, and non-critical media.
  • Do not lazy-load the hero image, logo if it is part of the main visible content, primary product image, or likely LCP element.
  • Set width and height or aspect ratio for images and videos to prevent layout shift.
  • For the likely LCP image, keep it discoverable in the initial HTML where possible, use the correct responsive image size, and consider fetchpriority="high" only for truly important above-the-fold images.
  • Myth: lazy loading always improves SEO. Reality: wrong lazy loading can delay LCP and make important content slower.

HTML5 and Semantic HTML Rule

Using modern HTML5 and semantic HTML is good because it helps structure content clearly for browsers, accessibility, crawlers, and AI extraction. It is usually not the first priority unless the current markup hides content, breaks headings, blocks links, prevents rendering, harms accessibility, or makes templates hard to crawl.

Best Use Worst Use Priority
Clear main, nav, header, footer, article, section, real links, readable headings, accessible forms, visible text content. Content built only in canvas, images, inaccessible widgets, broken buttons instead of links, missing headings, hidden text, or JS-only navigation crawlers cannot follow. P1 if important content or links cannot be crawled. P2 for template cleanup. P3 if markup is imperfect but crawl and UX are fine.

Page Builder Textbox and Heading Container Rule

Use this when someone asks whether an H2 and paragraph must be in separate page-builder text boxes or containers. The editor layout is not the SEO issue. The final HTML output is the issue.

Condition SEO Meaning Action
Page builder outputs a real h2 followed by real paragraph text. Good. It does not matter whether the editor used one textbox or two. Choose the editor setup that is easiest for formatting and maintenance.
Page builder makes heading text look like a heading but outputs only div, span, image text, or inaccessible content. Bad for structure, accessibility, and extraction. Use real heading and paragraph elements or fix the template/component.
Separate text boxes create many unnecessary wrappers and scripts. Usually not a ranking issue alone, but can add DOM bloat and performance risk if excessive. Check final DOM size, rendered HTML, mobile layout, and Core Web Vitals before calling it a problem.
  • Myth: H2 and paragraph must be in separate text boxes for SEO. Reality: Google reads the final HTML, not the page-builder editing experience.
  • Myth: separate text boxes automatically slow the page. Reality: noticeable delay happens only when the builder adds excessive DOM, scripts, styles, or layout work.

DOM Size Rule

DOM size means how many HTML elements and nested levels the browser has to manage. Large DOM trees can slow loading, rendering, memory use, and interaction.

DOM Condition Meaning Action
Lean DOM, visible content only, simple repeated components. Best condition. Browser has less work and interactions are usually faster. No action unless other evidence shows a problem.
More than about 800 body nodes. Warning level in Lighthouse-style checks. P2 if on important templates. Reduce unnecessary wrappers, hidden content, huge menus, repeated blocks, unused widgets, and unneeded page-builder markup.
More than about 1,400 body nodes. Bad condition. It can hurt load, rendering, interaction, and memory, especially on mobile. P1 for money pages, product/category templates, location templates, and pages with INP or LCP problems.
Very deep nesting or too many children under one parent. Can make styling and layout calculations expensive. Simplify component structure, split large lists, use pagination or virtual loading for huge lists, and remove hidden duplicate DOM.

Myth: DOM size is a direct ranking factor. Better rule: treat DOM size as a technical performance and UX risk that becomes important when it affects crawling, rendering, Core Web Vitals, mobile usability, or conversion.

Migration or URL Change

  • Create old-to-new URL mapping before launch.
  • Use correct redirects and preserve strongest equivalent pages.
  • Update internal links, canonicals, hreflang, sitemaps, schema URLs, and important backlinks where possible.
  • Monitor GSC, crawl errors, rankings, logs, and conversions after launch.

Domain Change and Site Move Rule

Use this when a site changes domain, subdomain, protocol, URL structure, CMS, design, or major content. If possible, change one thing at a time. A domain change plus redesign plus content rewrite makes it harder for Google to transfer signals and understand what changed.

Migration Check Best Condition Worst Condition Priority if Wrong
Old-to-new mapping Every important old URL maps to the closest equivalent new URL. Many old URLs redirect to homepage, irrelevant pages, 404s, or mixed destinations. P0 for money pages and high-traffic pages.
301 redirects Clean one-hop 301 from old URL to exact new URL. 302s, chains, loops, soft 404s, blocked old URLs, or missing page-level redirects. P0.
Change of Address Old and new domain properties are verified in GSC and the Change of Address tool is submitted when appropriate. Tool not used for eligible domain move, wrong property, missing www/non-www or subdomain variants. P1 after redirects are confirmed.
Canonicals New pages canonicalize to new URLs. Old pages either redirect or canonicalize correctly when redirects are not possible. Mixed old/new canonicals, self-conflicting canonicals, old domain preferred over new domain. P0 or P1 depending on affected pages.
Sitemaps New sitemap contains only canonical new URLs and is submitted in GSC. Sitemap still contains old URLs, redirected URLs, noindexed URLs, or mixed domains. P1.
Internal links All navigation, body links, hreflang, schema, canonical tags, media references, and important links point to new URLs. Internal links still point through old domain or redirect chains. P1 for templates, P2 for isolated links.
New domain health No manual actions, no leftover removals, crawlable robots, no development noindex, clean server responses. New domain has previous spam/manual actions, URL removals, robots blocks, noindex, or crawl errors. P0.
Monitoring Track old and new domain GSC, index coverage, sitemaps, crawl stats, rankings, traffic, conversions, and logs. Only checking rankings and not monitoring crawl/index transfer. P1.

Domain Change Notes

  • Google can take weeks for many small or medium site moves and longer for larger sites. Fluctuation is normal, but bad redirects or mixed canonicals are not normal.
  • Bing moving faster than Google does not prove Google is broken. Check Google-specific crawl, canonical, indexing, and Change of Address signals.
  • If Google keeps preferring the old domain, inspect canonical signals, redirects, sitemap URLs, internal links, external links, and whether old pages remain crawlable enough for Google to see the move.
  • Maintain redirects for at least 180 days and preferably longer. Keep the old domain controlled for at least a year when possible.
  • Do not use the Change of Address tool for simple HTTP to HTTPS, same-domain path changes, www to non-www changes, or hosting/CDN moves without visible URL changes.

ccTLD to Global Subfolder Migration Rule

Use this when a country domain such as example.ie or example.co.uk is moved into a global domain folder such as example.com/ie/ or example.com/uk/. Treat this as a high-risk regional migration, not a normal path cleanup.

Risk Area What Can Go Wrong Required Check Priority
Page-level redirects. Only the homepage redirects, or old country URLs redirect to the new homepage instead of equivalent pages. Map every old URL to the closest new URL and confirm clean one-hop 301 redirects at scale. P0.
Country signal loss. A ccTLD has clear country association. Moving to a generic domain subfolder changes that signal and can create volatility. Set expectations that recovery can take weeks or months and may settle at a different baseline. P1 expectation risk, P0 if redirects are missing.
Hreflang. Wrong, missing, non-reciprocal, or conflicting hreflang lets global, US, UK, or other regional pages compete with the target country page. Check self-referencing hreflang, return tags, x-default, language-region codes, sitemap hreflang, and rendered HTML. P0 or P1.
Canonicals. Country pages canonicalize to global pages, US pages, or old URLs. Country-folder pages should usually self-canonicalize unless there is a deliberate consolidation reason. P0 for country money pages.
Internal links and sitemaps. Navigation, body links, hreflang, sitemap, schema, or alternate links still point to old country domains or wrong regional pages. Crawl old and new URLs and compare internal links, sitemap URLs, canonicals, hreflang, schema URLs, and redirects. P1.
Regional cannibalization. The global site or another country section outranks the intended regional page. Compare ranking URLs by country, query, language, intent, canonical, hreflang, internal links, and page content. P1.
  • Do not promise a ranking boost from consolidating country domains into a global domain. The best realistic goal is clean signal transfer and recovery to a stable new baseline.
  • If traffic tanks after the move, first verify whether all old URLs redirect. Missing page-level redirects are a P0 blocker.
  • Compare successful and failed country migrations side by side: redirect coverage, hreflang, canonicals, sitemaps, internal links, backlinks, country traffic, and ranking URL changes.
  • Recover missed value by fixing redirects and updating high-value backlinks where possible, but do not pretend every lost position can be fully recovered after a messy migration.
  • Myth: moving from ccTLD to .com/country/ is only a URL change. Reality: it changes geo signals, link paths, hreflang dependency, internal architecture, and regional competition.

.co to .com Migration Rule

When moving from a .co domain to a .com domain under the same brand, do not think in terms of redirecting "the whole website" to the new homepage. Think in terms of preserving every important URL signal with exact one-to-one mapping.

  • Map every .co URL to the closest equivalent .com URL.
  • Redirect every old page with a clean one-hop 301 to the matching new page.
  • Handle blog subdomains separately if blogs live on a subdomain. Verify old and new subdomains in GSC and map their URLs too.
  • Use Change of Address only when the move qualifies and both old/new properties are verified.
  • Update internal links, canonicals, sitemaps, hreflang, schema URLs, social profiles, GBP, ads, email templates, and high-value external links.
  • Expect temporary ranking fluctuation. A careful migration reduces risk but does not make the move invisible to Google.
  • Ignore DR as the migration goal. Preserve real traffic, rankings, links, conversions, indexation, and user trust.

Website Redesign Rule

A redesign can improve SEO if it fixes crawlability, content clarity, conversion, UX, speed, internal links, author trust, and page structure. It can also harm SEO if URLs, titles, content, links, canonicals, schema, or templates change without mapping.

After Redesign Pattern What Can Happen How to Interpret
Clicks and impressions jump in first 28 days. Google may be discovering new content, better structure, new queries, or temporary volatility. Good sign, but wait several weeks and compare page/query-level movement before declaring permanent lift.
Conversions improve even if traffic is similar. The redesign may be better for business even before ranking changes mature. Track leads, revenue, forms, calls, demos, and landing page conversion rate.
Technical SEO is cleaner but authority is still weak. Technical fixes help access and clarity, but external authority may still limit rankings. Build legitimate mentions, links, partnerships, citations, proof, and PR assets.

Redesign myth: "If the first month improves, doing nothing will keep growth going." Reality: it may stabilize. Keep a 2 to 4 week measurement rhythm, protect winning pages, and choose next tasks by business impact.

Manual Action Recovery Rule

A manual action is not the same as normal ranking volatility. First read the exact message in GSC. The recovery plan depends on the manual action type.

Step Action Reason
1 Copy the full Manual Actions message, affected patterns, examples, and scope. Do not guess. A scaled content action, link action, hacked spam, structured data issue, or thin content issue needs different fixes.
2 Export GSC data for affected sections, especially pages with zero historical impressions, clicks, links, and keywords. Pages with no traction may be better removed, noindexed, merged, or redirected than repaired one by one.
3 Look for patterns: near-identical city/service pages, subject variations, AI-scaled content, scraped content, doorway pages, link schemes, UGC spam, or misleading structured data. Google usually acts on patterns, not just one ugly page.
4 Fix the cause, not just the wording. Remove, rewrite, consolidate, noindex, clean links, remove schema abuse, close spam holes, and document everything. Editing thin or scaled pages lightly may not fix the underlying abuse pattern.
5 Submit a reconsideration request only after the site is genuinely cleaned. Premature reconsideration wastes time and weakens the case.

Manual action timing can vary from days to weeks, and link-related or severe spam cases can take longer. Traffic may not fully return immediately even after revocation because rankings still need to be reassessed.

Thin Content Manual Action for Forums, UGC, and Large Sections

Use this when GSC shows a thin-content or little-added-value manual action for a folder, template, or UGC area, even if Google gives no exact example URLs.

Pattern to Audit What Can Be Wrong Action
No-reply or near-empty threads. Pages exist but do not answer anything useful. Noindex, remove, consolidate, or require useful replies before indexing.
Syndicated feeds, copied KB archives, imported content, or scraped summaries. Little original value beyond copied content. Remove, noindex, canonicalize, rewrite with original value, or add clear source/usefulness rules.
Duplicate threads, tag/search pages, empty profiles, thin category pages, or paginated low-value archives. Large indexable footprint with weak unique value. Use noindex, robots where appropriate, canonical cleanup, consolidation, and internal-link pruning.
AI replies, auto-generated summaries, or scaled thin answers. Looks mass-produced and not reliably helpful. Improve moderation, add human review, remove low-value output, and document the new policy.
Old content unchanged for years. Old pages can still be reassessed when Google recrawls, when sitemaps change, or when the section is reviewed. Do not assume age protects it. Audit by current quality and usefulness.
  • If a manual action names a path or folder, treat that path as the main evidence pattern even when exact URL samples are missing.
  • Recent robots, sitemap, internal-link, indexing, redesign, or reporting changes can cause Google to crawl or reassess old weak sections. That does not mean the recent change is the only cause.
  • For reconsideration, explain the root patterns found, actions taken, examples improved/removed/noindexed, new moderation rules, and why the issue should not return.
  • Myth: no example URLs means there is no real issue. Reality: partial manual actions can point to a pattern, folder, or site section.
  • Myth: forums cannot avoid thin content because UGC is messy. Reality: forums need indexation rules, moderation, consolidation, and quality thresholds.

19. Structured Data and Rich Result Rules

Structured data must describe visible page content accurately. It does not guarantee rich results or rankings.

Rich Results Test Rule

Use the Google Rich Results Test when checking whether Google can process the structured data on a public URL or pasted code snippet. It is best for testing live structured data eligibility, syntax, detected rich result types, errors, warnings, and rendered source locations.

Result Meaning Action Priority
Valid items detected with no critical errors. Google can process the structured data type found on the tested page. Good. Still verify that markup matches visible content and correct page type.
Valid items with warnings. The page may be eligible, but optional or recommended fields are missing. P2 for important money pages or rich-result pages. P3 if warning is minor or page has low value.
Invalid items or syntax errors. Markup cannot be processed correctly. P1 if rich results matter for the page. P0 only if the same broken implementation affects many high-value pages or creates misleading markup risk.
No items detected. No eligible structured data was found. Not always a problem. Add markup only when it matches the page type and visible content.
URL cannot be crawled. The test cannot access the page or required resources. P0 or P1 if the page should be publicly accessible and important. Check firewall, login, robots, server errors, redirects, or blocked resources.

Best result: correct structured data, matching visible content, correct page type, and no critical errors. Worst result: invalid, misleading, hidden, copied, or page-type-mismatched markup, especially review, product, local business, FAQ, or offer markup.

Page Type Common Structured Data Rule
Service or local page LocalBusiness, Service, Organization, BreadcrumbList, FAQPage if visible and useful. Use only accurate service, location, price, review, and business data.
Ecommerce product page Product, Offer, Review, AggregateRating, BreadcrumbList. Product merchant listing markup belongs on pages where shoppers can buy a specific product or variant, not generic category pages.
Category or collection page BreadcrumbList, ItemList where appropriate. Do not misuse single-product markup for a collection of unrelated products.
Article or blog Article, BlogPosting, Person, Organization, BreadcrumbList. Byline and author information should match visible content.
FAQ FAQPage only when questions and answers are visible and useful. Do not add irrelevant FAQ blocks to every page.

Schema Ranking and Rich Result Reality Rule

Use this when someone claims schema markup directly improves rankings. Structured data is useful for eligibility, clarity, entity disambiguation, and some rich-result appearances. It should not be sold as a standalone ranking strategy.

Schema Use What It Can Do What It Cannot Do Priority
LocalBusiness or Organization schema. Clarify real business facts such as name, URL, address, phone, hours, sameAs profiles, and service area when accurate. It does not replace GBP quality, reviews, local pages, citations, links, content, or proximity. P2 housekeeping, P1 if facts are wrong or missing across templates.
Product, Offer, Review, AggregateRating, JobPosting, Recipe, Event, or other rich-result schema. Can make a page eligible for specific search features when it follows Google requirements and matches visible content. Eligibility does not guarantee a rich result or ranking improvement. P1 when the rich result is important to the page type.
Schema added only to boost rank. May help search engines parse facts, but ranking lift should not be assumed. It cannot fix thin content, wrong intent, weak authority, poor UX, or weak conversion. P3 unless required for rich result eligibility or data clarity.
Review markup for local or service businesses. Can be valid only when it follows the specific review markup rules and the review is visible and appropriate for the page. Self-serving, third-party, hidden, copied, or policy-violating review markup can create manual-action risk. P0 if misleading or policy-risk markup is live.
  • Add schema because it accurately describes visible content and supports eligible rich results or machine-readable clarity.
  • For local service businesses, LocalBusiness schema is usually good housekeeping, not the main ranking lever.
  • For job pages and product pages, the right schema can be essential for search feature eligibility, so it may be high priority even if it is not a classic ranking factor.
  • Validate with Rich Results Test, Schema Markup Validator, source HTML, rendered HTML, and Search Console enhancement reports where available.
  • Myth: schema markup directly ranks pages higher. Reality: schema can improve eligibility and clarity, but useful content, intent match, authority, technical access, and search appearance still decide outcomes.
