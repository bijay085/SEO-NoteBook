# Page-Type Body Templates

Select the template from the dominant user activity. Use a hybrid only when two tasks are materially necessary. These are semantic and functional patterns, not mandatory visual designs.

## 1. Article, guide, or informational page

```text
article header → direct answer/abstract → primary figure or tool when essential → grouped TOC when useful → detailed sections → evidence/references → author/update context → related tasks
```

Required roles: subject, question/problem, answer, explanation, evidence, limitations, and next relevant task. Keep site navigation and share controls outside prose boundaries.

## 2. Service page

```text
service + provider/location H1 → direct value/scope → primary contact action → problems and services covered → process → credentials/evidence → pricing or estimate context → limitations/expectations → FAQs → contact action
```

Required roles: provider, service, customer, location or service area when relevant, scope, process, evidence, risk/limitations, and conversion action. Claims and credentials require supplied evidence.

## 3. Local service or location page

Inherit the service template, then require truthful business identity, service-location relationship, contact method, hours/availability when supplied, local evidence, and consistent NAP. Do not create unsupported local claims, offices, service areas, response times, licenses, reviews, or rankings.

## 4. Product page

```text
product identity → media → price/availability → variants and selection → primary purchase action → specifications → use/fit → delivery/returns/warranty → evidence/reviews → related products
```

Required roles: product, seller, offer, currency/unit, availability, variant, specification, buyer decision, transaction, and policy. Visible offer data and structured data must agree.

## 5. Category or listing page

```text
category identity/scope → concise selection guidance → filters/sort and applied state → recoverable item list/grid → pagination/load state → category evidence/guidance → related categories
```

Required roles: collection, membership rule, item, comparable attributes, filter, sort, result count/state, navigation, and availability when relevant. Client-only grids require a recoverable rendered state and truthful empty/error states.

## 6. Comparison page

```text
comparison question → alternatives and audience → disclosed criteria/method → consistent comparison → trade-offs → evidence and dates → suitability by case → decision path
```

Required roles: alternatives, shared dimensions, evidence, method, trade-off, audience, date, uncertainty, and recommendation basis. Do not change criteria between alternatives.

## 7. Tool or calculator

```text
task H1 → short instructions/input requirements → working tool → result with units and assumptions → method/formula → example → limits/privacy when relevant → related tasks
```

Required roles: input, type/unit, constraint, action, output, assumption, error, method, state, and limitation. Results must be understandable, keyboard-operable, and announced where needed.

## 8. Directory or provider listing

```text
directory scope/location → inclusion and ranking method → filters → provider records → comparable attributes → verification/date → pagination → contact/destination route
```

Required roles: directory scope, provider, location, category, inclusion method, ordering method, verification, date, and destination. Paid placement and ownership relationships must be disclosed.

## 9. Homepage

```text
entity identity and proposition → primary audience/tasks → core offerings → evidence/trust → navigation to task pages → primary conversion action
```

The homepage may route several tasks, but it still needs a clear entity identity and priority. It must not attempt to contain every service-page frame in full.

## 10. Contact or booking page

```text
contact purpose → available channels → form/booking interface → required information → response expectations → location/hours when supplied → privacy/consent → success and error states
```

Required roles: requester, recipient, channel, required data, consent, submission, confirmation, availability, and expectation. A request form must not represent unconfirmed availability as a booked appointment.

## 11. FAQ or Q&A page

```text
scope and audience → distinct questions → direct answers → qualifications/evidence → escalation or related task
```

Questions must be visible, specific, non-duplicative, and answered directly. FAQ structured data must match visible questions and answers and must only be used when applicable.

## 12. Review, forum, or community page

```text
topic/item identity → contribution/review records → author and date → rating/context when present → chronology/sort → moderation/verification method → response/report controls
```

Required roles: contributor, subject, contribution, date, source, moderation, verification, rating scale when present, and disclosure. Generated or curated material must not impersonate independent user contributions.

## Hybrid selection

Name the primary template first and the supporting template second, such as `Service + Tool`. Apply all global rules, all primary requirements, and only triggered requirements from the supporting template. Report conflicts between tasks rather than forcing every component above the fold.
